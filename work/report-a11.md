## Decisions

- The editor writes one full `CourseTreeEdit`; new nodes use the existing native UUID helpers and
  array order is the persisted order. Reordering uses named buttons only—no drag-and-drop or new
  abstraction.
- RHF owns form state and validation while the existing React Aria kit owns controls. Form resets
  are keyed to a changed `updatedAt`, so a same-version background refetch cannot discard dirty
  edits. Save passes the loaded tree to the existing authoring mutation, which carries its
  `updatedAt` as `expectedUpdatedAt`.
- `course_modified` stays neutral about who wrote: the existing save mutation refetches through
  `invalidateAfterCourseWrite`, and the form renders the newly stored version with copy noting the
  response may reflect the user's own earlier save.
- The guarded `/admin` layout exposes its authenticated actor to children. Only the admin branch
  mounts `admin.instructors()`; instructors see their own display name. A missing/failed admin
  picker renders the current owner read-only and leaves Save enabled.
- Status is separate from the full-tree form: draft publishes, published archives, archived
  restores. The slug disables when `publishedAt` is non-null, including archived courses; Delete
  renders only for drafts.
- A create replay reporting `slug_taken` invalidates the active course list, searches the refreshed
  list data for the slug and offers the matching editor when present. RHF's submitting state is
  exposed as `aria-busy` and disables create/save while each request is pending; A12 still owns the
  explicit editor double-submit evidence.
- A11 stays below the spec-flow threshold and retains the plan's A12 boundary: it adds no
  primary-read 503 retry state and no R40 test.
