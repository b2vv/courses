# Admin-рестайл — pre-draft acceptance + рев'ю-осі

  **повний прототип усього admin через GPT-плагін**, гранулярність = **спільні примітиви**

  на одній примітив-системі, ми перекладаємо на наші токени. Editor-рішення = перший зріз.
- **Автор:** Courses 2 (рев'ю-роль), 2026-10-14. Поділ: Courses 1 планує + пише brief для плагіна;
  Courses 2 — рев'ю, acceptance/осі, рев'ю перекладу в прод.
- **Фіналізувати остаточно на GATE 1** (формальний гейт spec-flow лишається); маршрут уже зафіксовано.

## Чому системно, не по-екранно (підстава фази)

«Скомкано/недороблено/кострюбато» — у спільному шарі, не в окремих екранах:
- admin-shell: на вузькому екрані лівий нав стакається згори й тисне контент донизу;
- data-table (список курсів, 46 рядків): на ~500px переносить title/slug/owner посеред слова — головний винуватець «кострюбатості»;
- карти/форми без спільної elevation-мови → панелі зливаються.
Публічні сторінки (лендинг/каталог/логін) сильні й на-бренд — **поза скоупом**.

## Acceptance (спостережуване, з магнітудою)

- **A1 Shell.** Лейаут не стакає нав над контентом і не тисне його; нав = колапс/drawer або
  бічний rail; контейнер має притомний max-width + гаттери. Доказ: скрини 360/768/1280 + 200% zoom
  без горизонтального скролу.
- **A2 Data-table.** Спільний табличний примітив деградує на вузькому (scroll-контейнер АБО
  stacked-cards), без переносу id/slug/owner посеред слова; **sticky row-actions** (дії рядка не
  губляться при горизонтальному скролі/вузькому — власникова вимога). Доказ: courses- і users-таблиці
  на 360px і 1280px читабельні, дії рядка досяжні; заголовки колонок асоційовані (клавіатура + скрінрідер).
- **A3 Form/card.** Спільні card (bg+border+shadow за нашою elevation) і field-примітиви; секції/панелі
  не зливаються.
- **A4 Успадкування.** Усі 8 admin-екранів на спільних примітивах, жоден не лишається на bespoke-CSS:
  `admin.index`, `admin.analytics`, `admin.courses.$courseId`, `…lessons.$lessonId`, `admin.learners`,
  `admin.users.index`, `admin.participant-reports`, `admin.refunds` (+ `admin` shell).
- **A5 Бренд/токени.** Лише наші токени (лайм+індиго, ваги 650/700/750, `--btn-primary-*`); жодного
  паралельного `--type/--size/--weight/--leading/--tracking` шару; axe/контраст зелені.
- **A6 Editor-зріз.** MUST зі `docs/lesson-builder/decision-editor-redesign.md` виконані.

## Intake-чекліст НА ПРОТОТИП (що brief/прототип мусить демонстровано закрити)

Перевіряю прототип від плагіна ДО перекладу в прод — кожен pain має бути видимо розв'язаний:
- [ ] **Один нав.** Жодного подвійного icon-rail+labeled; рівно одна навігація (+ окремий вихід «до клієнта»).
- [ ] **Elevation карток.** Тайли/панелі/секції мають bg+border+shadow і НЕ зливаються (analytics-тайли, картки списків).
- [ ] **Data-table narrow + sticky-actions.** Показано ≥1 таблицю на вузькому: деградація (scroll/stacked) без
  переносу id посеред слова, дії рядка лишаються досяжні (sticky).
- [ ] **participant-reports як ПАНЕЛЬ.** Репорт — картка/панель зі структурою (не голий «Label: value» дамп),
  статус = badge, дії прив'язані до панелі, не відірвані вправо.
- [ ] **Спільні токени без дрейфу.** Прототип на НАШІЙ системі: лайм+індиго, ваги 650/700/750, `--btn-primary-*`;
  жодного паралельного `--type/--size/--weight/--leading/--tracking`, без `--size-zero`/`--color-transparent`,
  без `color-mix`-CTA, без власної AdminShell.
- [ ] **Статуси = badge.** Статуси (course/user/role/report «Open») на єдиному pill-примітиві
  (`.ui-pill`), не на bespoke `.admin-*-status`; консистентні по екранах.
- [ ] **Learners spacing.** Статус не липне до лінку; елементи списку розділені (картка/дільник).
- [ ] **Empty states.** refunds/порожні черги мають притомний empty-стан, не голий текст на порожньому полотні.
- [ ] **a11y базово.** enabled-краї (не `isDisabled`), підписані/тултипнуті контролі (не сліпі іконки),
  44px, видимий фокус, 200% zoom без h-скролу, forced-colors.

## Рев'ю-осі (як перевірятиму кожен зріз)

1. **Стандарти (репо).** Токени-only, React Aria примітиви, без нових залежностей, scoped CSS,
   наші ваги, `--btn-primary-*`. Фільтр на вході з GPT-плагіна: відкинути чужі токени,
   `color-mix`-CTA, `--size-zero`/`--color-transparent`, власну AdminShell прототипу.
2. **A11y.** enabled-краї (no-op), **не** `isDisabled` (наш закритий focus-drop gotcha); підписані/
   тултипнуті контролі, **не** сліпі іконки; 44px, видимий фокус, 200% zoom без h-скролу,
   forced-colors, keyboard-нав таблиці/колекції. Правило «хто додає раховане — прибирає, хто читає —
   скоупить»: унікальність `role="status"`/єдиного H1 на екран.
3. **Адаптив.** 360 / 768 / 1280 на КОЖНОМУ екрані: нав не тисне контент, таблиця деградує,
   нема horizontal overflow.
4. **Візуальна когерентність.** Однакова card/table/form мова по всіх 8 екранах; співпадіння з
   публічним брендом (лайм+індиго), не індиго прототипу; elevation застосовано — панелі не зливаються.
5. **Спільний стан (головний урок репо).** Зміна спільного примітиву чіпає ВСІ admin-екрани →
   **повний e2e**, не таргетний (ламається поза дифом). Ordered `make check` локально (CI на білінгу).
6. **Spec/скоуп.** Кожен зріз = те, що GATE 1 заскоупив (спільні примітиви vs по-екранно); без
   creep у публічні сторінки (вони сильні, поза скоупом).

## Систематичні знахідки з живого admin (desktop 1366, 2026-10-14) — вхід у brief

- **Подвійний лівий нав** на всіх екранах: ~56px icon-rail + ~230px labeled-сайдбар дзеркалять
  одне одного → звести до одного. Головний «кострюбато».
- **Плоскі картки/панелі** скрізь (без тіні) → тайли/секції зливаються (та сама elevation-проблема, що в редакторі).
- **Еталон таблиці** — `users.index` (badge-ролі, pill-статус, per-row дії): інші таблиці підтягувати до неї.
- **Найсиріше** — `participant-reports` (голий текст-дамп + відірвані вправо кнопки) і порожній `refunds`.
- **Spacing-баг** у `learners`: статус липне впритул до лінку («…0cd6505dActive»).
- **Narrow (спільний shell, 500px):** нав стакається згори й тисне контент; горизонтальні таблиці
  переносять id/slug/owner посеред слова → data-table мусить деградувати (scroll-контейнер / stacked-cards).

## Відкрите (до GATE 1)

- GATE 1 формально підтверджує «спільні примітиви vs по-екранно» (маршрут уже за власником — спільні примітиви).
- Чи входить reader-режим у когерентність (editor↔reader) — SHOULD з editor-рішення.
- Per-екранний narrow для 5 нових екранів не переміряний індивідуально (в'юпорт вкладки зафіксовано 1366);
  додати живу вузьку перевірку кожного на рев'ю перекладу.
