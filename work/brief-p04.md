# Brief P04 — чотири точки перевірки: один сценарій відмови

Phase 9. Прочитай спершу: `docs/readiness/spec.md` (§3 D5; §6 R09), ADR 010, ADR 012,
`backend/internal/contracts/access/accesstest` (P03).

## Сценарій

Автентифікований **сторонній** користувач і **чернетка чужого автора** (рядок таблиці
`stranger × draft`). Кожна з чотирьох точок перевірки відмовляє, кожна — своїм контрактом:

| Точка | HTTP | Очікувана відмова |
|---|---|---|
| навчання | `course/adapters/http` — читання курсу для навчання | контрактна відмова курсу (з'ясуй точний статус і код: `course_forbidden` чи інший — за наявним контрактом, не вигадуй) |
| читання транскрипту | `transcript/adapters/http` — `GET /api/v1/learn/lessons/{lessonId}/transcript` | відмова ADR 010: відсутність транскрипту не відрізнити від заборони |
| сесія плеєра | `playback/adapters/http` — створення сесії | відмова сесії за наявним контрактом |
| nginx `auth_request` | `playback/adapters/http` — `authorize` | **403 без причини** (ADR 012) |

## Зроби

1. Знайди наявні contract-тести HTTP кожної точки (`*_handler_test.go` у трьох модулях). Для кожної
   точки має бути **один** тест, що називається з `R09` і проганяє саме цей сценарій: сторонній ×
   чернетка чужого автора → відмова за контрактом точки. Якщо такий тест уже є — перейменуй або
   додай до нього посилання на R09, не дублюй. Якщо немає — додай за наявним прецедентом цього
   файлу (ті самі фейки, той самий харнес).
2. Для контрасту в тому самому тесті — той самий користувач і **опублікований** курс → доступ
   дозволено. Це доводить, що відмова дається саме правилом, а не зламаною фікстурою.
3. Факти курсу в цих тестах мапляться за рядком `accesstest` (роль і статус), а не задаються вручну
   окремою логікою.

## NOT

Продуктовий код, SQL, домени, контракт, фронтенд, `docs/`, `work/tasks.md`, git — ні. Якщо

(file:line, що повертає точка).
