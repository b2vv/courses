## Обмеження, які визначають дизайн

1. **Бюджет логінів B19 на стелі** (`total=7`). Нових логінів не додавай: лише збережені стани
   (`admin`, за потреби `student`).
2. **Гонка з автопостановкою.** `asr-worker` раз на 60 с сам ставить у чергу розпізнавання для
   готових ассетів без чернетки (`EnqueuePending`, `cmd/asr-worker/main.go:30,136`). Ручне
   «Generate» після завантаження відео може отримати 409 `already_running`
   («Recognition is already running for this lesson.») — це правильна поведінка C10, а не збій.
   **Тести не мають залежати від того, хто поставив задачу:** чекай кінцевий стан чернетки в UI, а
   409 на ручному кліку вважай допустимим.
3. **Час.** Розпізнавання 4–6 с мовлення на CPU — ~7–10 с плюс черга, плюс до 60 с тіку, якщо
   першою спрацює автопостановка. Ставь `test.setTimeout` щедро (≈180–240 с на тест) і чекай
   станів через `expect(...).toBeVisible({ timeout })`, без фіксованих `waitForTimeout`.
4. **Для draft-ендпоінтів немає згенерованих моделей** (борг B-20). Там, де читаєш тіло запиту
   (C11), звужуй його явною перевіркою полів (`typeof`, `in`), без `as { … }`: інакше описка в імені
   поля тихо пройде.

## Зроби — новий файл `frontend/e2e/asr.spec.ts`

Один `describe` зі `storageState` адміна. Курс і урок сій через API, як у `transcript.spec.ts`,
з неймспейсом на прогін, і прибери за собою. Відео вантаж через UI.

- **C13** — урок із синусоїдною фікстурою `e2e-640x360.mp4` → після розпізнавання UI показує
  «No speech detected in the video», а не «Draft ready» з порожнім текстом.
- **C03** — урок із `e2e-speech-640x360.mp4`: автор бачить стан у процесі («Queued for
  recognition» або «Recognizing speech…») до завершення, потім «Draft ready». Перехід може бути
  швидким — зафіксуй, що проміжний стан спостерігався хоча б раз (`expect.poll` або
  `waitFor` одного з двох текстів), і не вимагай обох. **Гілку «після падіння — названа причина» в e2e НЕ пиши** — рішення рецензента (Courses 2,
  2026-09-24). Вона вже доведена деінде: unit `recognize_test.go` (named failures), integration C14
  (`failed/timeout` у БД), unit `LessonDraftField.test.tsx:146` («Recognition failed: model_error.»)
  і HTTP-контракт статусу чернетки. Чесної e2e-фікстури, що дала б названу відмову без маніпуляції
  томом `media-data`, немає, тож ніякого fault-injection. У `## Discussion` одним рядком зазнач, що
  гілку відмови покрито на інших рівнях.
- **C11** — селект мови пропонує лише локалі продукту й варіант автовизначення. На «auto» запит
  `POST …/draft/regenerate` **не містить** поля `language` (перехоплення `page.waitForRequest`,
  звуження тіла без `as`); на конкретній мові воно є й дорівнює вибраній.
- **C06** — готова чернетка з мовленням, потім заміна відео уроку (друге завантаження) → чернетка
  показана застарілою текстом «This draft was made from an older video. Regenerate to update.»
- **C17** — редактор транскрипту уроку відкритий, у ньому введено незбережений текст. Коли
  розпізнавання завершується, редактор **не** перемонтовується: введений текст на місці. «Load draft
  into editor» → у редакторі пропозиція «A recognized draft is ready» → «Load the draft» → рядки
  чернетки в редакторі.
- **C18** (e2e-частина) — завантаж чернетку в редактор і не зберігай; перегенеруй; перезавантаж
  сторінку → пропозиція відновлення показана як **застаріла** (застарілий варіант заголовка recovery,
  див. `TranscriptEditor.tsx` ~:128-131 і `en.ts`), а не звичайна.

Якщо рядки ділять дорогу підготовку (відео з мовленням, готова чернетка), дозволено спільний
`beforeAll` у межах файлу, але кожен тест стверджує лише свій рядок, і назва тесту починається з його
ID (`C03 …`).
