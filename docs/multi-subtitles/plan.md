# План — багатомовні субтитри (субтитри й транскрипт слідують за аудіо)

Фаза поза роадмапом §24. Продовжує multi-audio (S1–S7, S-backfill злиті; S7 = PR #106 → `main@5cbb44b`).
Статус: **ACCEPTED (plan-critic Codex, r6, 2026-11-14; r1–r5 BLOCKED, усі знахідки закриті — `_wip-plan-critique-{1..6}.md`). Код — лише після плану зрізу та його критики.** Кожен зріз нижче отримує власний `plan-msN.md`
і власний plan-critic перед кодом, як у multi-audio.

## 1. Мета й рішення власника

Урок мультимовний: для кожної аудіодоріжки субтитри на відео **і** текстова панель транскрипту
показуються **мовою вибраної доріжки**. Рішення власника (усі — 2026-11-14, AskUserQuestion у сесії
Courses 1):

- **O1 — «Слідують за аудіо».** Мова субтитрів визначається вибраною аудіодоріжкою, окремого
  вибору мови субтитрів немає (вимкнути субтитри можна, як і зараз).
- **O2 — джерело: ASR кожної доріжки + редактор.** Кожна Ready-доріжка розпізнається своєю мовою у
  власну чернетку; автор перевіряє і публікує; редактор отримує вибір мови.
- **O3 — fallback: «нічого + пояснення».** Нема опублікованого транскрипту мовою доріжки → субтитри
  й панель не показують іншу мову; плеєр і панель кажуть «немає субтитрів для цієї доріжки».
- **O4 — одна мова уроку.** Панель транскрипту (з пошуком) і субтитри завжди однієї мови, що й аудіо.
- **O5 — мова `und`-доріжки підтверджується автором при публікації.** Доріжка з невідомою мовою
  субтитрів не має; публікуючи її чернетку, автор підтверджує мову (підставлена виявлена whisper'ом,
  можна змінити), і доріжка отримує цю мову. Мовчазного перейменування за детекцією немає.
- **O6 — легасі: міграція ставить мову.** Наявним `und`-доріжкам, чий урок має опублікований primary-
  транскрипт, одноразово ставиться мова цього транскрипту (без колізій), маніфест перегенеровується —
  субтитри на наявних уроках не зникають.
(O5/O6 — 2026-11-14, AskUserQuestion, після ескалації plan-critic r2 finding 3.)
- **O7 — до Play панель показує транскрипт передбаченої доріжки** (2026-11-17, власник,
  AskUserQuestion; після MS4 plan-critic r1 finding 5: медіа вантажиться лише по Play, тож D7
  «до підтвердження — завантаження» прибрало б транскрипт до перегляду). Деталі й механізм —
  `plan-ms4.md` §0, M3.

Закрита раніше межа, що лишається: опублікований транскрипт **не чіпається** при зміні default-доріжки
(рішення S6, `docs/multi-audio/report.md` §S6).

## 2. Поточний стан (seam'и)

- **Сховище вже багатомовне.** `transcripts` PK `(lesson_id, language)` (`00007_transcript.sql`),
  `is_primary` з одним primary на урок (`00021`, partial unique index). Мова транскрипту — lowercase,
  `^[a-z][a-z0-9]{1,7}(-[a-z0-9]{1,8})*$`, 2–35 (`00007`; домен `transcript/domain/transcript.go:36-61`).
- **Читання** `GET /api/v1/learn/lessons/{id}/transcript[?language=]` (`transcript/adapters/http/handler.go:18`):
  без мови → primary, інакше перша за кодом (`adapters/postgres/repository.go:57-65`).
- **Запис** `PUT /api/v1/admin/lessons/{id}/transcript` з мовою в тілі: нова мова → новий рядок
  non-primary; перший рядок уроку → primary (`adapters/postgres/write.go:56-61`).
- **ASR — одна чернетка на урок.** `asr_drafts` PK `lesson_id` (`00008_asr.sql`), `source_leaf`
  default-доріжки (`00029`, S6). Pending = урок із Ready-ассетом без чернетки цієї генерації
  (`adapters/postgres/draft.go:67-87`); claim `ON CONFLICT (lesson_id)` (`:142-145`). Підказка мови
  береться з Regenerate автора (`application/recognize.go:81`); `transcribe.py --language` передає її
  у faster-whisper як є. Publish пише транскрипт мовою, яку визначила чернетка (`application/draft.go:154-189`).
- **Мова доріжки** — `[A-Za-z0-9-]{1,35}` зі збереженням регістру (`media/domain/audiotrack.go:267`,
  DB CHECK лише довжина `00025:13`); унікальність `(video_asset_id, language)` **з урахуванням
  регістру** (`00026`), тож `en` і `EN` можуть співіснувати. Embedded-доріжка нового аплоаду завжди
  `und` (`media/application/transcode.go:468-471`); backfill дає `und`, а `und-x-original` — лише при
  колізії (`00028:49`).
- **Редактор** редагує один транскрипт (без мови → primary, `LessonTranscriptField.tsx:82`, дефолт
  `'uk'`); чернетка іншою мовою над наявним транскриптом відхиляється (`TranscriptEditor.tsx:213-227`,
  рішення A13 «revisit when an editor for several languages exists», `docs/asr/report.md` §6).
- **Плеєр.** Маршрут бере транскрипт без мови й будує WebVTT (`routes/learn.$.tsx:214-220`), передає
  `captions`/`captionsLanguage` у `LessonPlayer` (`:290-291`); плеєр тримає один `<track>`, режим із
  пам'яті `captionsOn` (`LessonPlayer.tsx:593-601`). Мову вибраної доріжки плеєр знає лише після
  маніфесту (`onAudioTrack`, S7); нативний HLS (Safari) доріжку не перемикає.
- **Ціна ASR.** faster-whisper `large-v3-turbo` int8: **1.88 CPU-с на секунду аудіо**, у перерахунку
  на незавантажений воркер із 6 CPU — **~19 хв на годину уроку** (`docs/asr/spec.md:552-561`, §6.10;
  число 38 хв у `:294` — whisper.cpp). Один asr-worker.
- **Учень `/learn/$` — `ssr: false`** (`routes/learn.$.tsx:34`): SSR-шляху для транскрипту немає.
- **Черга ASR** дедуплікує за `asset:generation:<marker>` (`transcript/adapters/asynq/queue.go:61`) —
  дві доріжки одного ассета без чернеток дали б одну задачу.

## 3. Рішення (кожне закриває альтернативу)

### D1. Доріжка → транскрипт — лише рівність мов, без винятків
`captionLanguage(T) = lower(T.language)`. Субтитри й панель доріжки T — опублікований транскрипт мовою
`captionLanguage(T)`; нема — «немає» (O3). Доріжка з мовою родини `und` (`und`, `und-*`, «мова
невідома») **ніколи** не має субтитрів: плеєр показує «немає субтитрів для цієї доріжки», редактор —
шлях «вказати мову доріжки» (D5). `is_primary` у зв'язку **не бере участі** (лишається тільки для
читання без мови, яке D3 не змінює).
- Відкинуто (r1 blocker 1): `und`-default → primary. Контрприклад Codex: embedded `und` + `uk` primary →
  default на дубляж `en` → його публікація переносить primary на `en` → default назад на embedded →
  `en`-субтитри під українським аудіо. Плюс S5 пропонує `und` будь-якій доріжці
  (`media/domain/audio-track.ts:80`), тож «`und` default = легасі-оригінал» не випливає з даних.
- Відкинуто: колонка `audio_track_id` на `transcripts` — доріжки гинуть з ассетом при новому відео, а
  транскрипт переживає ассет (`authored_against_generation`); прив'язка за id осиротила б кожен
  транскрипт.
- Наслідок, явно: новий урок (embedded завжди `und`, `transcode.go:471`) не має субтитрів, доки автор
  не підтвердить мову при публікації (O5, D5). Наявні `und`-уроки з транскриптом отримують мову
  міграцією (O6, D8). Вручну написаний транскрипт під тегом `und` теж не показується — це виняток із
  рівності, свідомий: `und` означає «мова невідома», а не мову; редактор такий тег для транскрипту не
  пропонує (MS3). e2e, що покладаються на субтитри (`frontend/e2e/transcript.spec.ts`,
  `accessibility.spec.ts`), у MS4 ставлять мову доріжки через наявний PATCH.

### D2. Мова доріжки: форма транскрипту + унікальність без регістру
`validLanguage` доріжки вимагає, щоб `lower(language)` проходив правило мови транскрипту
(`transcript.go:36-61`); регістр зберігається (`en-US` валідне; `e`, `1x`, `a--b`, `x`×35 — ні).
Унікальність стає `(video_asset_id, lower(language)) WHERE state <> 'failed'` — тоді на ассеті
`captionLanguage` ↔ доріжка **1:1**, і кожна мова має рівно одну чернетку й одну вкладку (закриває r1
blocker 2, `en`/`EN`). DB CHECK + новий індекс у міграції; рядки, що не проходять, міграція **відмовляє**
з переліком id (без мовчазного переписування), доказ на populated data. Тести, що свідомо приймали
`'x'.repeat(35)` (`media/domain/audio-track.test.ts:38`), оновлюються. Усі сім мов, які пропонує S5,
`en-US`, `und`, `und-x-original` проходять.

### D3. Читання транскрипту не змінюється; додається інвентар мов
`GET …/transcript[?language=]` лишається як є (r1 nonblocking 5: редактор читає без мови,
`admin.courses.$courseId.tsx:348`). Плеєр завжди питає **з мовою** (D7). Новий admin-ендпоінт
`GET /api/v1/admin/lessons/{id}/transcripts` → `[{language, updatedAt, stale}]` — інвентар опублікованих
мов для вкладок редактора (MS2, openapigen).
- Відкинуто (r1 blocker 3): «без мови = транскрипт default-доріжки». Плеєр із запам'ятаною мовою `en`
  на уроці з default `uk` отримав би `uk`-текст, доки hls не повідомить вибір (`hls-media.ts:55`);
  серверна мапа default не знає вибору учня.

### D4. Чернетка ASR — на доріжку
`asr_drafts` ключується `audio_track_id REFERENCES audio_tracks(id) ON DELETE CASCADE` (lesson_id
лишається колонкою). Pending = Ready-доріжка останнього Ready-ассета уроку без чернетки цієї
(генерація, доріжка). Ідентичність доріжки входить **у всі** ключі, не лише SQL (r1 nonblocking 6):
TaskID черги (`queue.go:61` → `asset:generation:track:marker`), токени complete/recover, Query-ключі й
pending-мітки фронтенду (`admin-draft-queries.ts:103`, зараз lesson-scoped). Claim перевіряє
(lesson, asset, generation, track) одним statement'ом (C21). Видалення доріжки забирає її чернетку;
опублікований транскрипт її мови лишається (межа S6).
- **C09 переформульовується:** старий і новий ассет тепер — різні рядки, тож UPSERT-guard за
  генерацією (`draft_integration_test.go:338`) гарантію не тримає. Нова гарантія: чернетку доріжки
  не-останнього Ready-ассета claim відмовляє (`ErrDraftSuperseded`), а читання чернеток повертає лише
  чернетки доріжок останнього Ready-ассета. Механізм — той самий statement claim'у.
- **Знімок мови доріжки (r2 blocker 1).** Нова колонка чернетки `track_language` — `captionLanguage(T)`
  на момент **claim'у**, записана тим самим statement'ом, що й claim (повний тег, `en-us`, не підказка
  whisper'у). Наявна `language` лишається **виходом розпізнавання** (`recognize.go:105`). Міграція:
  існуючим чернеткам `track_language` = поточна `lower(language)` їхньої доріжки.
- **Staleness:** default-leaf-правило S6 (`domain/draft.go:178`) для чернетки доріжки замінюється на
  «генерація ≠ ready-генерація, або доріжки вже немає, або `track_language` ≠ поточна
  `captionLanguage(T)`», крім переходу `und`-родина → визначена мова (це крок O5, не перейменування).
  Так `en-US`→`en-GB` stale, `en-US` без змін — ні.
- Міграція: наявна чернетка → доріжка з leaf = `source_leaf` (NULL = `original` = embedded); без такої
  доріжки — видаляється (pre-launch), число на populated data у звіті MS2.
- Відкинуто: кілька мов в одній чернетці (jsonb за мовами) — один рядок мав би кілька станів
  одночасно, а claim/token/recovery (D8-6, C09) тримаються на «один рядок = одна спроба».

### D5. Мова розпізнавання й публікації
- **Визначена мова доріжки:** підказка whisper = перший subtag `captionLanguage(T)` (`en-us` → `en`),
  якщо він є в списку мов faster-whisper 1.2.1 (список звіряється у MS2 по встановленому пакету, не
  виводиться з граматики); інакше auto-detect із записом причини. Ручного override мови в Regenerate
  для такої доріжки **немає**: публікація пише транскрипт мовою `captionLanguage(T)` на момент
  публікації, а хибно позначену доріжку виправляють перейменуванням доріжки (S5 PATCH), після чого
  чернетка stale → Regenerate.
- **`und`-доріжка (O5):** auto-detect (як зараз). Публікація з UI MS3 = дві дії: (1) автор підтверджує
  мову (підставлена виявлена `language`, можна змінити) → PATCH мови доріжки (наявний media-ендпоінт,
  `handler.go:124`; переписує master до коміту метаданих, збій перезапису відкочує транзакцію —
  `media/adapters/postgres/audiotrack.go:274`; колізія → іменована помилка media, далі нічого);
  (2) publish. Оркестрація двох модулів у фронтенді — без імпорту media в transcript і без
  крос-модульного запису.
- **Контракт публікації (r2 blocker 2, r3 blockers 1–2).** Publish адресує **переглянуту спробу й
  підтверджену мову**: тіло = `{trackId, draftToken (updated_at чернетки, яку бачив автор),
  expectedTranscriptToken, language}`, де `language` — мова, під якою автор публікує: для визначеної
  доріжки — її `captionLanguage`, яку показував редактор; для `und`-знімка — мова, яку автор щойно
  підтвердив і поставив PATCH'ем (O5). Правило мови (одне для обох випадків): поточна
  `captionLanguage(T)` **=** `language` запиту, **і** (`track_language` = `language`, або
  `track_language` ∈ `und`-родина). Тож `und`→`uk`(автор)→`de`(інший автор) відмовляє: поточна `de` ≠
  підтверджена `uk` (`draft_language_mismatch`); виняток `und` не дає перейменуванню визначене→визначене
  пройти, бо мова зв'язана із запитом, а не лише зі знімком.
- **Чому `und`-знімок не старіє від перейменувань (r4 blocker 2 — заперечення з механізмом).** Правило
  «перейменування → stale → Regenerate» існує, бо для визначеної доріжки мова **входить у
  розпізнавання**: підказка whisper'у примусова (D5 вище), і текст `en`-підказки під `de`-аудіо —
  інша робота. Для `und`-знімка підказки не було: whisper розпізнав без мови (auto-detect), тож текст
  чернетки **не залежить** від того, як доріжку назвуть потім. Перейменування `und`→`uk`→`de` тим самим
  автором і публікація A під `de` — це O5 у прямому значенні («підставлена виявлена, можна змінити»):
  автор вирішує, якою мовою є вже почутий текст. Що захищає запит: поточна мова доріжки = `language`
  запиту (чужий rename між підтвердженням і публікацією відмовляє). Рядок приймання MS2: послідовність
  `und`-claim → PATCH `uk` → перерваний publish → PATCH `de` → publish(`de`) — успіх; та сама
  послідовність для знімка `en` → `draft_language_mismatch`.
- **Протокол блокувань (r3 blocker 2, r4 blocker 1).** Публікація блокує **один** ассет — той, якому
  належить чернетка: (1) `SELECT … FROM video_assets WHERE id = $draftAsset FOR SHARE`; (2) рядок
  доріжки `FOR SHARE`; (3) рядок чернетки `FOR UPDATE`; (4) транскрипт (наявний optimistic token).
  Блокування всіх ассетів уроку (r4) відкинуто: Ready-промоція бере **цільовий** ассет першим
  (`media/adapters/postgres/publish.go:32`), потім сусідів (`:43`), тож будь-який порядок «усі ассети»
  дає з нею цикл очікування (контрприклад Codex r4). З одним рядком циклу немає: публікація ніколи не
  тримає замок, якого чекає промоція, поки сама чекає іншого.
  Що саме гарантує замок. Писачі, що змінюють **факти самого ассета A чернетки** — мову чи існування
  його доріжок, його Ready-стан, його eviction/видалення — конфліктують з (1): rename і delete доріжки
  беруть `FOR UPDATE` ассета A до зміни доріжки (`audiotrack.go:271`), відео-промоція нового ассета бере
  A як сусіда (`publish.go:43`), eviction/delete A — `UPDATE`/`DELETE` рядка A.
  **Чого замок не дає й не мусить давати (r5 blocker 1).** Промоція завантаженої доріжки ассета B
  (`PromoteAudioTrack`, `awaiting_audio→ready`, `audiotrack.go:370,419`) без eviction не чіпає A, тож
  може закомітитись між перевіркою «A — останній Ready» і комітом публікації. Результат такого
  перемежування **еквівалентний послідовному порядку «публікація → промоція»**: промоція B не читає
  жодного рядка, який пише публікація (транскрипт, чернетка), а публікація читає лише закомічений стан
  на момент своїх перевірок, у якому B ще не Ready. Транскрипт штампований генерацією A
  (`authored_against_generation` = 1), тож після коміту B він читається stale — рівно як якби автор
  опублікував за мить до промоції. Отже гарантія D5 — **серіалізовність завершених результатів двох писачів** (стан після обох
  комітів дорівнює деякому послідовному порядку), а не «промоція чекає» і не однаковий знімок для
  кожного читача між комітами: читач між комітом B і комітом публікації бачить B з попереднім
  транскриптом або без нього — ні хибної мови, ні хибної свіжості це не дає. `draft_superseded` гарантовано лише
  для промоції, закоміченої **до** перевірки. Відкинуто: блокувати всі ассети уроку (deadlock r4) і
  змінювати `PromoteAudioTrack`, щоб він блокував сусідів (новий порядок замків у media заради властивості,
  яку серіалізовність уже дає). Якщо B-промоція спричиняє eviction A — вона бере A і конфліктує з (1). Писачі лише
  доріжки (append, cancel, audio sweep) конфліктують з (2) і чіпають тільки незавершені/failed доріжки.
  **Усі перевірки — після отримання замків**, кожна окремим statement'ом у READ COMMITTED, тож бачать
  закомічений стан після очікування: `draftToken` (інакше `draft_modified`), ассет чернетки — останній
  Ready уроку (інакше `draft_superseded`), правило мови, доріжка існує. Промоція, що закомітилась до
  перевірки, — публікація бачить новий Ready → `draft_superseded`; пізніша — див. серіалізовність вище. Пишеться транскрипт мовою `language` зі штампом
  **генерації чернетки** (`write.go:42` зараз штампує поточну Ready). MS2 доводить це integration-тестами
  гонки на справжньому Postgres із **примусовим** перемежуванням (бар'єр між кроками, не sleep):
  publish × rename, publish × delete, publish × відео-промоція, publish × `PromoteAudioTrack` без eviction
  (очікування: публікація успішна, транскрипт gen A, після коміту B — stale) і з eviction A (конфлікт на
  (1)), у обох порядках, з перевіркою відсутності deadlock-помилки й очікуваного результату кожного
  порядку.
- **Втрачена відповідь.** У тій самій транзакції чернетка отримує квитанцію
  `{published_draft_token, published_language, published_transcript_token}`. Квитанція перевіряється
  **першою**, до правил мови й superseded: повтор із тим самим `(draftToken, language)`, коли поточний
  токен транскрипту `published_language` ще = `published_transcript_token`, повертає його без запису
  (ідемпотентний успіх) — навіть якщо доріжку відтоді перейменували: публікація вже відбулась, а повтор
  лише питає її результат. Якщо транскрипт відтоді
  редагували вручну — звичайна `transcript_modified`; якщо чернетку перегенерували — `draft_modified`
  (новий `updated_at` чернетки не збігається з `draftToken`).
- Збій між O5-PATCH і publish лишає доріжку з мовою без транскрипту: субтитрів немає (O3), повтор —
  звичайна публікація з тією самою `language`.
- `is_primary` ASR-шлях не чіпає; ручний PUT — правило «перший = primary» без змін. Перенос primary
  (r1 D5) прибрано разом із винятком D1, тож гонки з `NOT EXISTS` (`write.go:59`) немає.

### D6. Редактор — вкладка на доріжку
Вкладки = Ready-доріжки **останнього Ready-ассета** (того, що грає учень; новий ассет у
processing/awaiting_audio вкладок не додає, доки не стане Ready — `LessonVideoField.tsx:48`), по одній
на доріжку (D2 гарантує 1:1 з мовою), + вкладки «без аудіодоріжки» для мов з інвентаря D3, яким не
відповідає жодна доріжка.
- Вкладка визначеної доріжки: транскрипт `?language=captionLanguage(T)` + чернетка цієї доріжки +
  Regenerate/Publish.
- Вкладка `und`-доріжки: лише чернетка; транскрипту немає; Publish = D5 (дві дії) з показаною
  виявленою мовою.
- Вкладка-сирота: редагування транскрипту (PUT), без чернетки й Regenerate; видалення — поза фазою.
- Ключ відновлення IndexedDB: `author:lesson` (`recovery.ts:177`) → `author:lesson:language`. Старий
  знімок без мови (поле опційне, `recovery.ts:30`) **не** відновлюється як «primary»: те, яку мову
  тоді читав редактор, із нього не відновити. MS3 задає явний шлях (показати як невизначений знімок
  з вибором вкладки або відкинути з повідомленням), колізію ключів і повторну міграцію; плюс перенос
  ключа `und`→мова після O5-PATCH.

### D7. Плеєр і панель — мова від підтвердженої вибраної доріжки
- `LessonPlayer` отримує новий вихідний prop (зараз `onAudioTrack` — лише між адаптером і плеєром,
  `LessonPlayer.tsx:46`) і повідомляє маршруту вибрану доріжку; маршрут питає
  `?language=captionLanguage(T)`; `und` → не питає, стан «немає»; відповідь `language: null` → «немає».
- **Межа переходу:** джерело вибору — `AUDIO_TRACK_SWITCHING` (`hls-media.ts:63`), а чутне аудіо
  змінюється пізніше (S7 заміряв до ~1.3 с до першого семпла дубляжу). Субтитри нової мови можуть
  з'явитися раніше за звук; MS4 вирішує межу (SWITCHING чи SWITCHED) і заміряє розрив, не обіцяє його.
- **До підтвердження вибору** (маніфест ще не розібрано) і **поки запит нової мови в польоті** —
  субтитрів немає, панель у стані завантаження; результат іншої мови не показується ніколи (рендер
  лише якщо `result.language === captionLanguage(selected)`; без `keepPreviousData`). Приймання
  включає старт із запам'ятаною не-default мовою і швидке перемикання туди-назад.
- Перемикання не перестворює media: captions лишаються поза залежностями створення instance
  (`LessonPlayer.tsx:368`); ефект `captionsOn` (`:595`) без змін; пам'ять `captionsOn` не змінюється
  станом «немає».
- Панель: при зміні мови пошук і follow-позиція скидаються (ключ панелі = мова) — пошук по іншому
  тексту безглуздий (`TranscriptPanel.tsx:22`).
- **Нативний HLS** (`hls-media.ts:113`): адаптер повідомляє мову ввімкненої доріжки з
  `video.audioTracks` — початковий вибір і події `change`/`removetrack`, де API є й мова непорожня;
  інакше вибір не підтверджено → «немає».
- Запам'ятована мова S7 порівнюється з маніфестом точно (`hls-media.ts:30`); після перейменування лише
  регістром (`en`→`EN`) вона не збігається і плеєр бере default — MS4 нормалізує порівняння до
  `lower()` (D2 робить це безпечним: на ассеті немає двох мов, що різняться регістром).

### D8. Легасі-міграція мови `und`-доріжок (O6)
Для кожного не-evicted Ready-ассета, чий урок має primary-транскрипт мовою P і на якому немає не-failed
доріжки мовою P (без регістру), **одна** не-failed доріжка `und`-родини стає P. Вибір детермінований:
default → embedded → найменший id; решта `und`-доріжок ассета — пропуск (наприклад, `und` і
`und-x-original` на одному ассеті: P отримує одна). Число змінених і пропущених із id — у звіті. SQL-міграція лише змінює `audio_tracks.language`; маніфест на диску вона переписати не
може, тому той самий зріз додає одноразову ідемпотентну команду media-worker'а «перегенерувати master
для всіх Ready-ассетів із БД» (той самий `RegenerateMaster`, `media/application/audiotrack.go:81`) і
запускає її в dev/e2e-потоці після міграцій. Команда — окремий режим `cmd/media-worker`, що не
стартує recovery/sweep/черги/HTTP (`main.go:60`) і завершується; іде через серіалізовану регенерацію
репозиторію (`media/adapters/postgres/audiotrack.go:297`), а не напряму через writer, тож безпечна проти
конкурентних змін метаданих і повторюється. Evicted ассети пропускає. Ненульовий код при будь-якій
помилці; e2e-потік падає на ньому. MS4 (активація D1 у плеєрі) вимагає, щоб команда в цьому потоці
пройшла. Між міграцією й командою маніфест старий — субтитрів
`und`-доріжка не має (безпечно, O3). Доказ на populated data: число змінених / пропущених рядків,
маніфест після команди містить нову мову. Heartbeat і таймкоди
  обговорень — за позицією уроку, від мови не залежать.

## 4. Зрізи

Порядок: MS1 → (MS2 + MS3 однією поставкою) → MS4. Плеєр — **останнім**: до MS3 автор не мав би шляху поставити мову
`und`-доріжці через публікацію, і субтитри зникли б з кожного нового уроку на час між злиттями.

- **MS1 — backend media: мова доріжки (D2, D8).** Валідація домену, DB CHECK, case-insensitive індекс,
  міграція з відмовою на невідповідних рядках і нормалізованих колізіях (з id), легасі-міграція D8 +
  команда регенерації master, доказ на populated data; frontend-валідація доріжки
  тим самим правилом. Повний `make integration` (змінюється злита поведінка media).
- **MS2 — backend: ASR на доріжку + інвентар (D3 інвентар, D4, D5).** Міграція `asr_drafts`,
  pending/claim/complete/recover/TaskID на доріжку, підказка мови й список faster-whisper, publish
  мовою доріжки з `draft_language_mismatch`, HTTP чернеток на доріжку й інвентар (openapigen,
  `openapi_contract.go:54-88`), контракт публікації D5 (draftToken, ідемпотентність). **MS2 і MS3 —
  одна поставка (r3 blocker 3):** окремі зрізи з власними планами, критикою й комітами, але один PR і
  один ordered gate. Новий контракт публікації (trackId, draftToken, language) старий lesson-scoped
  клієнт дати не може, а аліас без нього опублікував би неперевірену спробу або іншу доріжку
  (`draft_handler.go:116`) — тому ні аліасу, ні проміжного злиття бекенду без редактора. Integration (C09 у новому формулюванні, C21 на доріжку), повний e2e;
  e2e: дві доріжки з мовленням (наявні flite-фікстури `e2e-speech-*`) → дві чернетки.
- **MS3 — frontend: редактор мов (D6, D5-UI).** Вкладки, чернетка/Regenerate/Publish на вкладку,
  `und`-публікація з установкою мови, ключ відновлення з переносом; e2e: автор публікує дві мови.
- **MS4 — frontend: плеєр і панель (D7).** i18n «немає субтитрів для цієї доріжки»; unit; e2e на
  реальному стеку: дві доріжки (`en`, `de`) + транскрипти обома мовами → перемикання змінює мову
  субтитрів і панелі; старт із запам'ятаною `de`; швидке перемикання; доріжка без транскрипту →
  «немає»; `und` → «немає»; оновлення наявних caption-e2e (мова доріжки через PATCH). Замір затримки
  появи субтитрів після перемикання.

## 5. Перевірка (на кожен зріз)

Ordered `make check` (format-check → … → e2e) зеленим на фінальному коміті зрізу; незалежне рев'ю
Codex `exec` хвилями до SHIP; рядки приймання зрізу закриваються доказом зі шляху продакшну (не фейком).
Злита спільна поведінка (media-мова, `asr_drafts`) — повний `make integration` і повний e2e.

## 6. Ліміти (магнітуда або механізм)

- **Ціна ASR множиться на доріжки:** ~19 хв роботи воркера (6 CPU, незавантажений) на годину аудіо
  **на кожну** доріжку, послідовно, один worker (`docs/asr/spec.md:552-561`): година уроку з трьома
  доріжками — ~57 хв до останньої чернетки. Паралельних worker'ів фаза не додає.
- **Мова доріжки — довіра автору:** доріжка `en` з німецьким мовленням отримає примусову підказку `en`
  і текст неправильною мовою. Механізм виправлення: перейменувати доріжку → чернетка stale →
  Regenerate. Автоматичної перевірки мови немає.
- **`und`-доріжка без субтитрів**, доки автор не підтвердить мову при публікації (O5) або не вкаже її
  вручну; легасі-уроки — D8.
- **Осиротілий транскрипт** плеєр не показує ніколи (D1), редактор показує (D6); видалення — поза фазою.
- **Нативний HLS без `video.audioTracks`** → субтитрів немає (D7); e2e нативний шлях не покриває
  (Chromium грає через hls.js), лише unit із фейковим AudioTrackList.
- **Перемикання субтитрів** коштує один `GET …/transcript?language=` (`no-store`) на мову, якої ще нема
  в кеші Query; затримку заміряє MS4.
- Машинний переклад поза фазою: whisper перекладає лише в англійську, інших перекладачів у стеку немає.

## 7. Відкриті питання (технічні, у планах зрізів)

- MS2: точний список мов faster-whisper 1.2.1 з установленого пакета; форма TaskID.
- MS3: шлях для старих знімків відновлення без мови.
- MS4: межа переходу субтитрів (SWITCHING чи SWITCHED).
