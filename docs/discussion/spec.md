## 1. Навіщо ця фаза

Фаза 7 — синхронізований навчальний досвід: транскрипт (`7a`, закрита) і розмова про відео поряд
із ним. `7b` дає студентам коментувати **момент** уроку: коментар несе мітку часу, клік по ній
перемотує плеєр — та сама механіка, що в транскрипті. Бесіда відкрита для всіх, хто бачить урок,
тож оплата пізніше обмежить її тим самим правилом, що й перегляд, без нової логіки доступу.

## 3. Обсяг — що будуємо

### D1. Модуль `discussion`

Новий доменний модуль `backend/internal/discussion` — `domain` / `application` / `ports` /
`adapters` (`postgres`, `http`), залежності всередину. Власні типи `Actor`, `Course`, `Comment`.
Модуль **не імпортує** інших модулів; факти (власник і статус курсу, `display_name` автора,
тривалість `ready`-ассета уроку) читає власним SQL, як `playback`/`transcript` (ADR 013).

- `Course.CanBeViewedBy(actor)` — рівно `return access.CanView(…)` (читання **і** публікація, Q3).
- `Comment.CanBeEditedBy(actor)` — лише автор.
- `Comment.CanBeRemovedBy(actor, course)` — автор ∨ адмін ∨ власник курсу (Q4).

### D2. Модель і міграція `00009_discussion.sql`

Коментар: `id`, `lesson_id` (FK, `ON DELETE CASCADE`), `author_id` (FK users), `parent_id`
(null = корінь; інакше — корінь того ж уроку), `body`, `position_ms` (null або ≥ 0),
`created_at`, `edited_at`, `removed_at`.

- Тіло: після trim 1..2000 символів Unicode; розмітка не рендериться (plain text).
- Мітка часу — лише в кореня, необов'язкова; вимагає `ready`-ассет уроку і
  `0 ≤ position_ms ≤ тривалість`. Відповідь мітки не несе.
- Відповідь — лише на **корінь** (Q2): `parent_id` мусить бути наявним, не видаленим коренем
  того ж уроку.

### D3. Правила й коди помилок

| Дія | Хто | Відмова |
|---|---|---|
| Читати гілки уроку | `CanView` (Q3) | анонім → 401 `authentication_required`; без права → 403 `course_forbidden` (та сама відмова, що в транскрипті, ADR 010); невідомий урок → 404 `lesson_not_found` |
| Опублікувати корінь / відповідь | `CanView` | 400 `comment_body_invalid` / `comment_position_invalid` / `comment_parent_invalid`; 403 `origin_forbidden` / `course_forbidden`; 409 `comment_thread_full` — понад 200 не прибраних відповідей на корінь, перевірка атомарна (план X4) |
| Змінити | лише автор | 403 `comment_forbidden`; 404 `comment_not_found`; 409 `comment_removed` |
| Прибрати | автор ∨ адмін ∨ власник курсу (Q4) | 403 `comment_forbidden`; 404 `comment_not_found`; повторне прибирання — 204 (ідемпотентно) |

Прибирання **стирає тіло** безповоротно й лишає рядок: корінь без відповідей зникає зі списку,
з відповідями — показується заглушкою «Коментар видалено». Зміна ставить `edited_at` («змінено»);
історії правок немає.

### D4. Читання

`GET` віддає корені сторінками по 50 (курсор, найновіші першими) і **всі** відповіді кожного
кореня (найстаріші першими). Кожен елемент: `id`, `author.displayName` (null, якщо автора
видалено — UI пише «Колишній учасник»), `body` (null, якщо прибрано), `positionMs`, `createdAt`,
`editedAt`, `removed`, і **можливості глядача** `canEdit`, `canRemove`, обчислені сервером — фронт
не повторює правило, лише показує рішення бекенду (принцип D7 фази готовності).

### D5. HTTP і контракт

| Операція | Шлях |
|---|---|
| Список | `GET /api/v1/learn/lessons/{lessonId}/comments?cursor=` |
| Опублікувати | `POST /api/v1/learn/lessons/{lessonId}/comments` `{ body, positionMs?, parentId? }` → 201 |
| Змінити | `PATCH /api/v1/learn/comments/{commentId}` `{ body }` → 200 |
| Прибрати | `DELETE /api/v1/learn/comments/{commentId}` → 204 |

Усі чотири — в `openapi.yaml` з першого дня, фронт — через Orval (урок B-20). Мутації проходять
`sameOrigin`; відповіді `Cache-Control: no-store`.

### D6. Фронтенд

Панель «Обговорення» на сторінці уроку поряд із транскриптом. Мітка часу — кнопка, що викликає
`onSeek(positionMs)` (та сама механіка, що в `TranscriptPanel`); у формі — «Прив'язати до поточного
моменту». Відповіді, зміна, прибирання — за `canEdit`/`canRemove`. Названі стани: завантаження,
порожньо, помилка. Збій обговорення не ламає урок — панель не suspend-иться, як транскрипт.
React Aria, ≥44px, клавіатура, видимий фокус, light/dark, 200% зум. Серверний стан — Query,
ключі скоуповані уроком; після власної мутації — інвалідація, без real-time.

### D7. Глобально лічене — хто додає, той і прибирає (AGENTS.md)

- Четвертий `CanBeViewedBy` → `access_mapping_ast_test.go` `expectedMethods` 3 → 4 у **тому ж**
  слайсі, що додає метод. Цей тест — **лічильник**, тож сам почервоніє, якщо забути.
- `shared_rules_test.go` `TestTheAccessPredicateAgreesAcrossModules` **перелічує** модулі
  (`viaCourse`/`viaPlayback`/`viaTranscript`, рядки 37–52), а не рахує їх: з четвертим модулем він
  лишиться зеленим і мовчки перевірятиме три з чотирьох. Тому гілка `viaDiscussion` додається в
  той самий слайс. Це єдине місце, що пінить «усі копії мапінгу згодні»: AST-тест бачить лише
  форму `return access.CanView(…)`, а не чи правильні поля змаплені.
- Таблиця `accesstest` проходить і через SQL адаптера `discussion` (як P03 для трьох модулів).
- Нові `role="status"` на сторінці уроку: e2e шукає їх **у межах панелі**, не за позицією на сторінці.
- e2e-дані run-scoped і прибираються після прогону.

## 4. Чого не робимо

Real-time (WebSocket/SSE/polling); сповіщення; реакції й лайки; згадки `@`; розмітку, HTML,
вкладення; історію правок; пошук по коментарях; пагінацію відповідей; скарги, чергу модерації,
огляд усіх коментарів курсу, блокування авторів — це **робоче місце інструктора** (§24 п.3, п.4 з
поправкою Q4); аудит модерації (хто саме прибрав — не зберігається); per-user ліміт публікацій
(лишається `zone=api`, §7).

## 7. Ризики

1. **Флуд.** Єдиний запобіжник — `zone=api` 10 r/s, burst 20, **за IP** (`nginx.conf:21,117`).
   Кілька акаунтів з одного NAT або один повільний спамер під лімітом пройдуть. Per-user ліміт і
   модерація масштабу — робоче місце інструктора.
2. **Корінь із дуже багатьма відповідями** віддається повністю — обмежено cap 200 відповідей на
   корінь (план X4: ≈ 400K символів тіла в одній відповіді `GET` у найгіршому разі). Пагінація
   відповідей лишається поза фазою.
3. **Відео уроку замінили** — старі мітки можуть вийти за нову тривалість. Мітка лишається,
   перемотка обмежується плеєром (`seekTo` clamp, `LessonPlayer.tsx:405`); окремої позначки
   «застаріло» немає.
4. **`display_name` видно всім глядачам курсу** — публічність імені тепер ширша, ніж у Phase 3.
5. **Модерація до робочого місця — лише точкова:** власник курсу бачить коментарі, тільки
   відкривши урок; огляду по курсу немає (§4).

## 8. Відкриті питання — для плану

- Курсор: `created_at` + `id` чи лише `id` (UUIDv7?) — вирішує план за наявним генератором ID.
- Чи ставити колонку `removed_by` для тексту заглушки («видалено автором / модератором») — зараз
  не зберігається (§4, аудит). Наслідок, який треба прямо сказати замовнику: помилкове
  прибирання власником курсу в `7b` **безповоротне й непростежуване**.
- **Межа мітки — третій читач тривалості `ready`-ассета** (з рев'ю GATE 1). `course` клампить при
  читанні, `playback` — при записі, а `discussion` **відхиляє**; функції різні, але межа мусить
  збігатися: `position_ms == тривалість` дозволено (як `want=100` у
  `TestThePositionBoundAgreesAcrossModules`). План вирішує: спільний предикат чи гілка `discussion`
  у цьому крос-тесті — щоб не повторити B07 (читач без межі).
- **Відповіді без пагінації** (§7 п.2): у плані заміряти або поставити м'який cap на відповіді одного
  кореня — необмежена кількість є вектором навантаження.
- **`role="status"` уже є на сторінці уроку** (`TranscriptPanel`, «Відео замінили»). K22 (axe) і будь-який
  селектор статусу на рівні уроку не припускають, що він один.
