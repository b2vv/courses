# lesson-builder — specification (ЩО / ЧОМУ)

Намір, не реалізація. Стек, файли й архітектура — у `plan.md` (крок 4). Рішення й припущення
живуть у [assumptions.md](assumptions.md).

## Проблема

Урок сьогодні несе `Title` + **один плоский рядок `Description`** + `Position` + `IsPreview`
(`backend/internal/course/domain/authoring.go:62`); відео, транскрипт, прогрес і дискусія
прив'язані до уроку окремо (playback/transcript/discussion модулі). **Структурованого тіла
уроку не існує** — немає способу скомпонувати текст, зображення, колонки, завдання чи галерею
навколо відео.

Власник хоче авторувати **багату сторінку уроку** з гнучким, але контрольованим набором секцій —
власний аналог react-page, але БЕЗ його ваги: react-page відкинуто (залежність Material-UI,
важкий вкладений grid/cell-DOM, супровід); Tiptap як **layout**-рушій не підходить (це rich-text,
не page-builder), але його MIT-ядро — правильний шар саме для тексту.

Два реальні приклади уроків (від власника, 2026-10-12) показують, що потрібна модель — **не вільне
drag-полотно**, а впорядкований список типізованих секцій:

- **Езотерика:** відео зверху → текст (замовляння) → ряд з 2 колонок (зображення + пояснення) →
  завдання внизу. Частина уроків без відео: просто текст + зображення.
- **Б'юті:** відео-уроки як і планувалось + портфоліо автора як **галерея** (масштабована,
  багато зображень).

Візуальний орієнтир клієнтської поверхні для обох брендів — totaltypescript.com (відео-центрична
сторінка, чиста читацька колонка, outline-навігація, щедра типографіка).

Fork-per-brand: цей репозиторій — ШАБЛОН; власник копіює код під кожен бренд. Тому редактор має
покрити обидва описані бренди одним набором секцій; white-label абстракції/плагінів немає.

## Рішення (ухвалені до spec, з assumptions.md)

- **Модель = власний структурований документ уроку**, не сторонній drag-рушій. Впорядкований список
  типізованих секцій; застосунок володіє і схемою, і рендерером. Craft.js/Puck/react-page **не**
  беруться: обидва реальні уроки виражаються секціями+пресетами, тож вільне полотно не виправдане.
- **Формат — власний, валідований, версійований** (не сирий JSON стороннього рушія): стабільні типи
  й ID незалежні від імен React-компонентів, версія схеми, обмежена вкладеність, типізовані
  медіа-референси, явний шлях міграції старих документів.
- **Rich-text у секціях `text`/`task` — на Tiptap (MIT-ядро)**; layout і решта секцій — власні.
- **Відео лишається першокласним типом уроку** — переюз наявного playback (+ транскрипт, прогрес,
  timestamped-дискусія): один відео-слот на урок, не довільні відео-блоки.
- **Зображення — через наявний media-pipeline** (nginx `/media/`, upload-модуль), не base64 у
  документі.
- **Вкладеність — лише depth-1** всередині `row`; решта секцій пласкі. Це тримає DOM легким,
  a11y посильною, рендер читача простим.

## Користувацькі сценарії

1. **Автор** відкриває урок в адмінці → додає секції (відео / текст / зображення / ряд-колонки /
   завдання / галерея), впорядковує їх (вгору/вниз/перемістити), редагує вміст; усе — з клавіатури,
   drag — як підсилення, не єдиний спосіб.
2. **Автор езотерики** будує: відео → текст-замовляння → ряд [зображення | пояснення] → завдання.
   Інший урок — без відео: текст + зображення.
3. **Автор б'юті** будує відео-урок + секцію-галерею з портфоліо (N зображень, лайтбокс).
4. **Автор** зберігає чернетку, далі публікує; опублікована ревізія — те, що бачить учень.
5. **Учень** відкриває урок → бачить легку семантичну сторінку (відео-плеєр з наявною поведінкою,
   текст, зображення, колонки, галерея, завдання); редакторський JS не вантажиться.
6. **Автор** редагує двомовний урок (uk/en) → вміст секцій існує по локалях; структура спільна.

## Acceptance criteria

Спостережувані й перевірні. «Тверді» — суть фази; «м'які» — бажані, межу уточнює GATE 1.

- **AC1 (тверде).** Документ уроку має **власну валідовану версійовану схему** з фіксованим набором
  типів секцій; невідомий тип або порушення структури **відхиляється на бекенді** (не зберігається).
  Перевірка: контрактний тест на валідацію (валідний приймається, ворожий/невідомий — відмова з
  явним кодом).
- **AC2 (тверде).** Набір секцій v1: `video` (0..1), `text` (0..N), `image` (0..N), `row`
  (1–3 колонки, діти лише `text`/`image`, depth-1), `task` (0..N). **`gallery` НЕ входить у цю
  фазу** — винесено у наступну фазу `portfolio` (GATE 1, 2026-10-12). Вкладеність глибша за 1
  відхиляється. Перевірка: тест на кардинальність і глибину.
- **AC3 (тверде).** Автор додає/видаляє/переупорядковує секції й редагує вміст **повністю з
  клавіатури**: видимий фокус, контролі ≥44px, працює на 200% zoom, світла/темна. Перевірка: e2e
  клавіатурою + axe.
- **AC4 (тверде).** Учнівська сторінка уроку рендериться **без редакторського коду/JS**
  (Tiptap-editor, drag, toolbar) у клієнтському навантаженні; вивід — семантичний HTML. Перевірка:
  grep/аналіз бандла learn-шляху + DOM-перевірка.
- **AC5 (тверде).** Рендер документа **безпечний**: збережений вміст не передається як довільний
  HTML/теги; rich-text обмежений allowlist-ом марок, текст екранований, URL валідовані; ворожий
  документ рендериться безпечно. Перевірка: тест на XSS-вектор у text/посиланні/медіа-URL.
- **AC6 (тверде).** Відео-секція **зберігає наявну поведінку** уроку: playback, транскрипт,
  прогрес, timestamped-дискусія, завершення уроку — не зламані. Перевірка: наявні playback/
  transcript/discussion e2e зелені.
- **AC7 (тверде).** Захищений вміст уроку **не протікає** у широко-видиму outline-відповідь:
  тіло уроку доступне лише тому, кому `CanBeViewedBy` дозволяє контент (не лише preview-outline).
  Перевірка: контрактний тест доступу (preview-gl# бачить структуру курсу, але не тіло закритого уроку).
- **AC8 (тверде).** Чернетка vs публікація: автор зберігає чернетку, публікує атомарно; учень
  бачить лише опубліковану ревізію. Перевірка: e2e (чернетка невидима учневі; публікація застосовує).
- **AC9 (тверде).** **Нова підсистема довільних зображень.** Наявний media-pipeline суто відео
  (tus по `videoId`, HLS, thumbnail'и з відео; nginx віддає лише `/media/p/<hex>/hls/`, решту
  `/media/` відмовляє). Фаза будує шлях завантаження/сховища/авторизації/віддачі **довільних
  зображень** для секцій `image`/`row`-image: не base64 у документі, авторизований serve через
  nginx, CSP (`img-src`) не ламається. Перевірка: зображення вантажиться автором і віддається учневі
  новим шляхом під auth; документ/бандл не містить base64-байтів.
- **AC10 (тверде).** Поточна поведінка збережена: усі наявні e2e-флоу зелені; плоский `Description`
  мігровано у документ (або співіснує) без втрати наявних уроків. Перевірка: ordered `make check`,
  міграція доведена на наповнених даних.
- **AC11 (м'яке, з магнітудою).** DOM учнівської сторінки лишається пласким: виміряти к-сть
  DOM-вузлів типового уроку (езотерика-приклад) проти наївного вкладеного підходу; зафіксувати число.
- **AC12 (м'яке).** Двомовність (uk/en): вміст секцій існує по локалях з правилом фолбеку;
  структура спільна. Межу (чи в цій фазі) уточнює GATE 1.

## Out of scope

- **Галерея / портфоліо / before-after** — винесено у наступну фазу **`portfolio`** (GATE 1,
  2026-10-12): сотні зображень, альбоми/колекції, пара «до/після» + UI-порівняння, пагінація/lazy.
  Це друга підсистема поверх підсистеми зображень цієї фази; тримаємо її окремо, щоб кожна фаза
  лишалась поставною (Codex-ризик «другого продукту»). Секція `gallery` з'явиться там.
- **Вільне drag-полотно / довільний грід** (Craft.js/Puck/react-page-стиль) — обидва реальні уроки
  виражаються секціями+пресетами; полотно повертаємо лише якщо майбутній дизайн його вимагатиме
  (з доказом).
- **Довільні відео-блоки** — один наявний відео-слот на урок; multi-video — окреме рішення.
- **White-label / тема per-brand / плагіни** — fork-per-brand знімає це; кожен бренд темізує свою
  копію. totaltypescript-вигляд — референс для майбутнього дизайн-проходу, не ця фаза.
- **Редизайн адмінки** — білдер живе в наявній NorthWind-консолі.
- **Прод-деплой** — тест-режим (Р1); доводимо збіркою, e2e, локальним Compose.

## Рішення GATE 1 (закрито 2026-10-12, підтвердив власник)

Повний запис — у [assumptions.md](assumptions.md). Стисло:

- **Q1 — секції v1:** `video`/`text`/`image`/`row`/`task` усі в v1; `gallery` → фаза `portfolio`.
- **Q2 — міграція:** плоский `Description` → односекційний `text`-документ, старе поле прибрати
  (pre-launch; у сідах прозових описів немає).
- **Q3 — i18n:** схема locale-aware від початку; editor v1 авторує одну локаль (uk), чистий seam під
  en; повний перекладацький UI — наступна фаза.
- **Q4 — rich-text allowlist v1:** абзаци, h2/h3, жирний/курсив, ul/ol, посилання (валідований
  http(s)). Без код-блоків, без довільного HTML.
- **Q5 — gallery:** сотні зображень + before/after пари → підсистема, винесена у фазу `portfolio`.
- **Q6 — публікація:** дві ревізії `draft`+`published`, публікація копіює draft→published атомарно;
  без історії/відкату у v1; учень читає лише `published`.
- **Q7 — task:** стилізований rich-text у v1; структуроване завдання зі здачею — окрема фаза.
- **Q8 — білдер:** окремий маршрут редактора уроку (`admin.courses.$courseId.lessons.$lessonId` або
  еквівалент); явні «Зберегти чернетку»/«Опублікувати»; без автозбереження у v1.
- **Q9 — спайк:** доводить на одному реальному уроці: (1) save→reload→edit→міграцію схеми;
  (2) learn-рендер без редакторського JS (вимір бандла); (3) клавіатурне впорядкування + depth-1
  `row` на 200% zoom; (4) одне довільне зображення через новий upload→store→nginx-serve під auth;
  (5) ворожий документ рендериться безпечно під enforcing CSP + тіло не протікає в outline.
