Source tests were read, not executed; their existence is evidence of intended behavior, not a claim that they pass today.

Scope: `_client`, `_shared`, `core/config`, `core/session`, `modules/auth`, `persons/model`, and the immediately referenced persons/auth HTTP adapters. These suggestions adapt the reference to courses' stricter hexagonal architecture, request-scoped SSR and TanStack Query. They do not authorize starting identity or introducing a second client framework.

## Eight practices to adopt

1. **One transport boundary, constructed with dependencies.** `ApiRequestService` owns URL/header/body construction, `AbortSignal`, native fetch and the response read; specialized clients receive configuration and callbacks. `initApi` injects the base URL instead of importing environment access from an inner layer. Adopt that separation as an immutable `create…({baseUrl, fetch, timeoutMs, cookie?})` in courses composition; pass the resulting transport into the generated Orval client/adapter. Native fetch remains outside routes/presentation. Keep the port domain-facing and the concrete transport inside adapters. The mutable factory implementation is explicitly not adopted. Sources: [request service](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/request/api-request.service.ts:49), [public/private client wiring](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/clients/api-private-request.service.ts:16), [bootstrap URL injection](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/providers/http-clients.ts:27). `core/config/api.ts` contains only `AUTH_ENDPOINT`; it is not an environment/config service to copy.

2. **Parse response bytes according to the endpoint contract.** The dedicated `readFetchBody` separates JSON/text/form/blob handling and preserves a JSON error response even for a blob endpoint. For the current JSON-only catalog, explicitly read JSON and retain response status/request ID. Do not add unused binary/form handlers, media proxying, or heuristic envelope unwrapping. A catalog `200` with an empty body, HTML, broken JSON, or an incompatible content type is an invalid response, never an empty catalog. The reference catches parser errors and returns `undefined`; courses must correct that behavior, as described below. Source: [body reader](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/http-body/read-fetch-body.ts:21).

3. **Treat decoded payload as `unknown` until runtime validation succeeds.** `validateWire` uses `schema.safeParse` and returns a discriminated validation result. `runValidated` makes HTTP failure and schema failure separate paths, so a rejected `200` cannot masquerade as HTTP success. Apply this before mapping generated Course DTOs into domain: validate actual received fields, dates/status and pagination shape rather than trusting generated TypeScript. Let schema inference carry the validated type; do not cast `unknown[]` back into generated DTO arrays. Sources: [validateWire](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/utils/validate-wire.ts:11), [runValidated](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/utils/run-validated.ts:65), [wire behavior tests](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/utils/__tests__/run-validated.test.ts:29).

4. **Use explicit result branches and map them at the boundary that owns the meaning.** The reference has `FetchResult → HttpWireResult → ServiceResult`, with separate HTTP and validation branches. Adopt the discriminated-result principle; courses needs fewer representations if one typed adapter result suffices. Preserve a validated backend error code and bounded request ID; map those into domain/application errors such as `course_not_found`, `invalid_query`, `dependency_unavailable`, plus explicit invalid-response/timeout categories. Raw `Response`, HTTP headers, server payloads and numeric status policy stay in the adapter. A malformed error envelope still represents the observed non-2xx HTTP failure but must not acquire a guessed business code. Sources: [wire result](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_shared/http-wire-result.ts:9), [result mapper](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_shared/http-wire-to-service-result.ts:16), [service error shape](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_shared/service-result.ts:4).

5. **Keep DTO projection explicit and honest.** `personListCardFromDto` selects known fields, normalizes empty optional strings and leaves unavailable material as `null`; `mapPersonLookupItemFromDto` produces a small domain-facing read model. Adopt pure Course mapper functions in `adapters/api`, with no DTO imports in domain/application. Do not fabricate titles, totals or capabilities when required data is missing. courses has an explicit pagination body, so reference fallbacks based on missing headers are unnecessary. Sources: [card mapper](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/persons/model/mappers/person-list-card.mapper.ts:31), [lookup mapper](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/persons/model/mappers/person-lookup.mapper.ts:22), [persons service constructor and flow](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/persons/model/person-list.service.ts:18).

6. **Preserve caller cancellation and bound the complete read operation.** The reference combines caller signal and deadline with `AbortSignal.any`, creates the deadline once per read, and excludes both abort and elapsed deadline from retry. Its guards distinguish `AbortError` from `TimeoutError`. Apply the same distinction to fetch *and body consumption*: navigation cancellation is a control event, a deadline is a visible failure, broken JSON is invalid data, and an interrupted body stream is an I/O failure. Keep the original abort reason instead of manufacturing an unrelated error. courses should choose one explicit SSR-friendly time budget and one retry owner; an expired operation cannot retry against its spent signal. Sources: [deadline combination](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/request/api-request.service.ts:132), [error guards](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/error/error-unknown.ts:11), [timeout behavior test](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/request/api-request.service.test.ts:411), [retry termination](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/utils/retry-with-backoff.ts:1).

7. **Translate Result failure into a thrown typed error only at the Query adapter boundary.** `unwrapServiceResult` turns a service result into data or an `ApiError` for TanStack Query; `authCommands` invokes it in `mutationFn`. Adopt this seam for catalog query functions so failure does not enter Query as successful cached `{ok:false}` data. Keep domain use cases framework-independent. Query keys include all normalized URL parameters; query functions pass the provided signal inward. Error serialization for SSR must retain only safe discriminants/request IDs and must work after hydration without depending solely on `instanceof`. Source: [Query result bridge](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/error/unwrap-service-result.ts:7), [command-layer use](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/auth/auth.commands.ts:11). The serialization recommendation is an inference from courses' SSR requirement, not behavior verified in Cassiopeia.

8. **Keep future session policy and UI effects outside generic transport.** Reference token/refresh middleware receives callbacks, refresh policy has one gate, concurrent refreshes share one in-flight operation, and logout bounds the best-effort server call before local cleanup. `SessionEffects` separates realtime/broadcast effects from session operations. Retain these as Phase 3 design guidance only: request-scoped cookie forwarding is the current requirement, not bearer refresh or logout implementation. Keep localized UI descriptors separate from backend messages; the auth module resolves translation keys at render time so locale changes update them. Sources: [refresh middleware](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/middleware/refresh-token.middleware.ts:16), [session gate](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/auth/session-token-gate.ts:32), [single-flight refresh](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/auth/auth.refresh.ts:163), [bounded logout](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/session/auth-session.ts:24), [injected effects](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/session/session-effects.ts:9), [localized error descriptor](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/modules/auth/lib/map-login-error.ts:24).

## Three things to avoid or defer

1. **Avoid SPA global session/client state in SSR.** The reference exports shared mutable API clients, uses `setBaseUrl`, memoizes service factories, keeps global session snapshots/effects and defaults token storage to `localStorage`. These choices can cross request/session boundaries or fail on the server. courses must create dependencies and QueryClient per SSR request, forward cookies only to its configured Go API origin, and never dehydrate cookie/header values. Bearer storage, refresh scheduling, cross-tab locks and logout are Phase 3 work. Sources: [shared clients](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/providers/http-clients.ts:39), [service singleton](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/persons/model/person-list.factory.ts:5), [snapshot cache](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/session/auth-session-store.ts:17), [token store globals](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/session/tokens.ts:146).

2. **Avoid overlapping cache/retry/middleware systems.** The reference can attach a GET memory cache keyed only by URL and run a retry runner beneath Query. courses already gives server-state ownership to Query; a second cache risks stale state, loss of response metadata and, if shared with future identity, cross-user reuse. Keep the catalog transport uncached, use explicit Query cache policy and no hidden transport retries. Do not import the full middleware inheritance hierarchy, generic `qs` serializer, blob handling or auth middleware for two read endpoints. Query behavior must remain bounded and reproducible on SSR. Sources: [URL-only cache](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/middleware/cache.middleware.ts:14), [retry rules](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/utils/should-retry.ts:2), [request runner](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/request/api-request.service.ts:201). The current reference private client explicitly sets `enableMemoryCache: false`; this concern is about copying the optional mechanism into courses, not a claim that its private client currently caches.

3. **Avoid lossy parsing, type casts and transport leakage.** `readFetchBody` catches all read/parse failures; `baseFetch` casts its result to `T`; persons HTTP output weakens validated items to `unknown[]` and its service casts them back. `ServiceError` carries raw HTTP body/method inward, and development diagnostics log full URL/error/raw response. courses' stricter boundary excludes those patterns: never suppress malformed response or cancellation, never assert generic payload safety, keep HTTP details in adapters, and emit only safe operation/status/duration/request-ID fields. No raw body, cookies, query-bearing URL or token appears in logs. Sources: [swallowed body error](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/http-body/read-fetch-body.ts:63), [generic cast](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/request/api-request.service.ts:83), [weak wire type](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/persons/api/person-list.http-client.ts:13), [service casts](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/persons/model/person-list.service.ts:30), [raw diagnostics](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/utils/run-validated.ts:81), [full URL logger](/Users/strelia/projects/cassiopeia/cassiopeia-admin-ui/src/core/api/_client/middleware/error-logger.middleware.ts:8).

## Proposed courses failure matrix

This matrix is a decision suggestion for C03 tests; it does not claim implementation or passing verification.

| Observation | Adapter outcome | Query/UI implication |
|---|---|---|
| 200 + validated published courses and pagination | Map into Course domain result | Hydratable data |
| 200 + syntactically broken JSON, HTML, empty required JSON, schema mismatch | Explicit invalid response | ErrorState, no fabricated empty catalog |
| Known non-2xx + validated `{error:{code,message,requestId}}` | Map recognized stable code; retain safe request ID | Correct error/not-found branch |
| Non-2xx + malformed/unknown error body | Safe failure from observed HTTP status; no guessed domain code | Generic error, safe diagnostics |
| Fetch rejects before response, signal still active | Network failure | Bounded retry only if explicitly configured |
| Response body stream fails, signal still active | Network/body-I/O failure | Distinct from JSON syntax failure |
| Caller cancels before headers or during body consumption | Original cancellation/control outcome | Obsolete result never replaces the active query |
| Read deadline expires before headers or during body consumption | Timeout failure | Visible error, no retry against elapsed budget |
| SSR requests A/B use different cookies concurrently | Independent transport instances | A never forwards/caches/dehydrates B's state |

Recommended local seam tests: MSW malformed/unknown bodies and HTTP error envelopes; injected fetch/body-stream rejection and abort; timeout before/during body read; reversed A/B query completion; two concurrent SSR cookie contexts; generated-client regeneration; no DTO imports in domain/application. Source-code review used `rg`, `cat`, `sed` and read-only Git revision/status inspection. No Cassiopeia tests or running services were invoked.
