# Фаза `learning` — огляд навчання і блокування з черги (spec)

> ЩО і ЧОМУ. Стек/файли/архітектура — у `plan.md` після GATE 1. Статус: **GATE 1 пройдено 2026-10-08** (власник: «Наче все ок» — G1–G7 як є).
> (2026-10-08, Courses 1). Рішення власника 2026-10-08: будувати всі три залишки enrollment, вести як фазу.

## Проблема

Enrollment (PR #8) дав одне авторитетне членство `course_grants` (active/blocked/revoked) і **ростер
одного курсу** з прогресом і блокуванням (`GET /teach/courses/{id}/roster`, `…/participants/{userId}/block`).
Лишилось три прогалини (`docs/enrollment/report.md` §6, `docs/instructor/report.md` §5):

1. **Немає огляду по всіх курсах.** Інструктор із кількома курсами мусить відкривати ростер кожного
   окремо, щоб зрозуміти, хто в нього вчиться, хто застряг і хто заблокований.
2. **Адмін не має такого огляду по всій платформі** — лише довідник користувачів і чергу скарг.
3. **Блокування з черги модерації неможливе.** Черга показує коментар/відгук і **лише ім'я автора**
   (`CommentAuthor.displayName`, `Review.authorDisplayName` — ідентифікатор автора навмисно не
   віддається). Щоб заблокувати порушника, інструктор має знайти його в ростері за іменем, а імена
   не унікальні.

## Користувацькі сценарії

1. **Огляд інструктора.** Інструктор відкриває «Учні» в `/teach` → бачить кожного учня своїх курсів
   одним рядком: ім'я, на яких своїх курсах він учасник, стан і прогрес на кожному, остання активність.
   Фільтрує за курсом і станом, шукає за іменем, гортає сторінками.
2. **Огляд адміна.** Адмін відкриває той самий огляд у `/admin` — по всіх курсах платформи.
3. **Дія з огляду.** З рядка учня — перехід у ростер відповідного курсу (там уже є блокування/скарга).
4. **Блок із черги.** Інструктор у черзі модерації свого курсу тисне «Заблокувати автора на курсі»
   біля коментаря або відгуку → автор лишається учасником (дивиться), але більше не коментує й не
   пише відгуків на цьому курсі (`CanCommunicate`, як блок із ростера). Повторна дія — «Розблокувати».

## Ключові рішення (на GATE 1)

- **G1. Форма огляду — рядок на учня, курси всередині.** Учень = людина; його членства в моїх курсах —
  список у рядку (курс, стан, прогрес). Альтернатива «рядок на пару учень×курс» дублює людину на кожному
  курсі — відкинуто як шумну для мети «хто в мене вчиться».
- **G2. Хто видимий:** членства `active` і `blocked`; `revoked` — ні (як ростер; відкликаний — не учень).
- **G3. Приватність:** без email — і в огляді інструктора, і в адмінському (як ростер; адмін має email у
  довіднику користувачів, огляд дає посилання туди). Видалений акаунт — анонімний рядок, як у ростері.
- **G4. Остання активність** = найпізніший `lesson_progress.updated_at` учня на курсах у видимості
  глядача; немає прогресу → «ще не починав».
- **G5. Блок із черги — за ідентифікатором коментаря/відгуку, не користувача.** Сервер сам визначає
  автора й курс; `userId` автора у відповідь черги **не** додається (приватність черги лишається).
  Блок — той самий перехід членства, що з ростера (одна правда, один аудит).
- **G6. Межі блоку — за рангом ролі** (уточнення власника 2026-10-08: «адмін може заблокувати будь-кого
  статусом нижче»). Ранг: `student` < `instructor` < `admin`. Блокувати можна лише учасника курсу (є
  членство) **нижчого рангу, ніж той, хто блокує**: адмін — інструкторів і студентів (зокрема власника
  курсу, якщо той є учасником), але не інших адмінів; інструктор-власник курсу — лише студентів. Рівний
  або вищий ранг, або автор без членства — відмова з названим кодом. Правило одне для блоку з черги і з
  ростера. Відгук автора лишається видимим (блок — це мют, не видалення; видалення — окрема дія модерації).
- **G7. Розмір:** без жорсткої стелі; keyset-пагінація по учнях (як ростер, 20 за замовчуванням, до 100).

## Приймальні рядки (Lo — learning overview)

| Рядок | Що доводиться | Рівень доказу (план) |
|---|---|---|
| Lo01 | Інструктор бачить кожного учня своїх курсів рівно одним рядком; курси інших інструкторів не потрапляють | integration + e2e |
| Lo02 | У рядку — курси учня **лише з видимості глядача**, кожен зі станом і прогресом (той самий % що ростер) | integration |
| Lo03 | `revoked` не показується; учень лише з revoked-членствами не має рядка | integration |
| Lo04 | Остання активність = max `lesson_progress.updated_at` по видимих курсах; без прогресу — null | integration |
| Lo05 | Фільтр за курсом (лише свій; чужий courseId → 403/404 з кодом), фільтр за станом, пошук за іменем | contract + integration |
| Lo06 | Keyset-пагінація стабільна при вставці нового учня між сторінками; без дублів і пропусків | integration |
| Lo07 | Email не віддається ні інструктору, ні адміну; видалений акаунт — анонімно | contract |
| Lo08 | Студент і не-інструктор отримують 403 на огляд інструктора; не-адмін — на адмінський | contract + e2e |
| Lo09 | Адмін бачить учнів усіх курсів; той самий формат рядка | integration + e2e |
| Lo10 | З рядка — перехід у ростер курсу | e2e |
| Lo11 | UI огляду: клавіатура, видимий фокус, ≥44px, світла/темна, 200% тексту, axe | e2e |
| Lo12 | Блок автора коментаря з черги → членство `blocked`; автор далі дивиться, не коментує (`CanCommunicate`) | integration + e2e |
| Lo13 | Блок автора відгуку з черги → те саме; відгук лишається видимим | integration + e2e |
| Lo14 | Відповідь черги не містить ідентифікатора автора (контракт не розширено) | contract |
| Lo15 | Відмови з названими кодами: автор рівного/вищого рангу (інструктор→інструктор/адмін, адмін→адмін); автор без членства; чужий курс; невідомий коментар/відгук. Дозволи: адмін→інструктор, адмін→студент, інструктор→студент | contract + integration |
| Lo16 | Розблокування з черги відновлює `active`; повтор блоку/розблоку ідемпотентний або з названим конфліктом — як у ростері | integration |
| Lo17 | Блок із черги і з ростера дають той самий запис (стан, аудит) | integration |

## Out of scope

- Експорт (CSV) огляду; масові дії над кількома учнями.
- Прогрес нижче за курс (по уроках) в огляді — він у ростері/навчанні.
- Блок на всій платформі (є адмінське відключення акаунта, Phase 3); блок у межах одного курсу — лише так.
- Сповіщення учню про блок.
- Зміна ролей (§24 п.10), деплой.
