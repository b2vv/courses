## 3. Рішення дизайну

### D-1. Доказу-куки немає взагалі ⟵ C16, C5, C6

**Редакція 3 скасовує сутність, яку редакції 1 і 2 намагались полагодити.** Ідентичність
браузера вже несе **сесійна кука логіну** — кожен логін пише окремий рядок `user_sessions`.
Отже:

| Що було в ред. 2 | Що стало |
|---|---|
| кука `playback` з непрозорим id | **немає** |
| ендпоїнт продовження доказу | **немає** — володіння поновлює heartbeat (D-8) |
| суперечка про `Path` | **зникла разом із кукою** |
| «витіснений просить продовження й воскресає» (C5) | **неможливо**: продовжувати нема чого |
| heartbeat не має чим себе назвати (C6) | **зникло**: його називає сесійна кука |

**Грант ADR 005 на 3 хвилини переїжджає в TTL ключа Redis.** Володіння живе `ownershipTTL`
(конфіг `playback/adapters/http/config.go`, дефолт 180 с); heartbeat поновлює його, тиша
довша за TTL — знімає. Короткоживучий грант зберігся; носій змінився з куки на запис.

Доказ **не є** bearer-здатністю на конкретне відео: право на кожне відео перевіряється на
кожному запиті (спека A6, уточнена після GATE 2).

### D-2. Edge ⟵ C1, C2, C3, C10, C22, C25

**Витяг id відео з нормалізованого `$uri`, а не передача сирого рядка.** Go авторизує
**ідентифікатор**, не шлях, який йому довелося б розбирати — це знімає весь клас
розбіжностей між тим, що авторизували, і тим, що nginx резолвить у файл.

У блоці `http`:

```
limit_req_zone $binary_remote_addr zone=media:10m rate=120r/s;
proxy_cache_path /tmp/nginx-auth levels=1 keys_zone=media_auth:1m
                 max_size=8m inactive=60s use_temp_path=off;
map $uri $media_video {
  default "";
  "~^/media/hls/(?<v>[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12})/" $v;
}
map $cookie_courseforge_session $session_absent {
  default 0;
  "" 1;
}
```

У `server`:

```
location ^~ /media/hls/ {
  # НОСІЙ значення, не косметика: у сабреквесті $uri дорівнює /_media_auth, тож map
  # там дасть порожньо. Цей set змушує обчислити змінну в rewrite-фазі БАТЬКА, а
  # сабреквест успадковує його кеш змінних. Приберете set — X-Video-Id поїде порожнім,
  # ключ кеша схлопнеться в "<сесія>|", і одна кука відкриє будь-яке відео.
  set $video_for_auth $media_video;
  if ($video_for_auth = "") { return 403; }   # ГАРД порожнього id, не носій значення

  auth_request /_media_auth;
  error_page 500 502 503 504 = @media_denied;  # у лістингу, а не лише в прозі ⟵ C10
  limit_req zone=media burst=240 nodelay;
  add_header X-Content-Type-Options nosniff always;
  add_header Referrer-Policy strict-origin-when-cross-origin always;
  add_header X-Frame-Options DENY always;
  add_header Cache-Control "private, no-store" always;
  root /;
}
location @media_denied { return 403; }
location ^~ /media/ { return 403; }   # source/, thumbnails/, temporary/ лишаються закритими
location = /_media_auth {
  internal;
  set $api http://api:8080;
  proxy_pass $api/internal/playback/authorize;
  proxy_pass_request_body off;
  proxy_set_header Content-Length "";
  proxy_set_header X-Video-Id $video_for_auth;
  # Без цього рядка кеш НЕ вмикається: Authenticate ставить Cache-Control: no-store
  # на кожну відповідь (identity/adapters/http/handler.go:125,245-247).
  proxy_ignore_headers Cache-Control Expires Set-Cookie;
  proxy_cache media_auth;
  proxy_cache_key "$cookie_courseforge_session|$video_for_auth";
  proxy_cache_valid 200 204 30s;
  proxy_no_cache $session_absent;
  proxy_cache_bypass $session_absent;
  proxy_connect_timeout 1s;
  proxy_read_timeout 2s;
}
```

Виправлення проти редакції 1, кожне з наслідком:

| ⟵ | Було | Стало | Що ламалось |
|---|---|---|---|
| C1 | `proxy_cache` без `proxy_cache_key` | явний ключ `$cookie_playback\|$media_video` | дефолтний ключ не містив куки: одне 204 30 с обслуговувало **будь-кого, включно з анонімом** |
| C2 | `^~ /media/` | `^~ /media/hls/` + `^~ /media/` → 403 | віддавались `source/<id>/original` — сирі майстер-файли |
| C3 | `X-Original-URI $request_uri` | `X-Video-Id` із `map` над `$uri` | авторизували сирий незадекодований рядок, а файл брали з нормалізованого |
| C10 | `zone=media` не оголошена, `burst=...` плейсхолдер, `proxy_cache_path` лише в прозі | усе оголошено | **nginx не піднявся б** |
| C22 | `proxy_pass` літералом | `set $api …; proxy_pass $api;` | після заміни контейнера api тримався б старий IP — весь медіатрафік 500 |
| C25 | один `add_header` | усі чотири повторено | `add_header` у location **гасить** успадковані nosniff / Referrer-Policy / X-Frame-Options |

Виправлення редакції 3, кожне заміряне рецензентом у контейнерах:

| Було в ред. 2 | Стало | Що ламалось |
|---|---|---|
| `proxy_cache` без `proxy_ignore_headers` | `proxy_ignore_headers Cache-Control Expires Set-Cookie` | `Authenticate` ставить `no-store`, тож **кеш не вмикався взагалі**: три однакові запити = три звернення до Go, вікно A32 = 0, G9 мертвий |
| ключ `$cookie_playback\|$media_video` | `$cookie_courseforge_session\|$video_for_auth` | ключ не містив сесійної куки: після прогріву запит **без сесійної куки** отримував 200, не дійшовши до Go — умова 1 з D-3 обходилась |
| `if` мотивований як валідація | `set` як носій + `if` як гард, із коментарем | `if` був несучим випадково; рефактор «прибрати зайву валідацію» відкрив би одну кукою будь-яке відео |
| `error_page` лише в прозі | у лістингу | рівно дефект C10, за який план убив редакцію 1 — і я його повторив |

**Кеш живе в `/tmp` ⟵ виправлення власного заміру редакції 1.** Причина в редакції 1 була
названа хибно (нібито властивість образу). Заміряно наново під реальним compose-конфігом:

```
$ docker compose run --rm --entrypoint sh nginx -c 'id -u; stat -c "%n %U:%G %a" /tmp /var/cache/nginx; ...'
101
/tmp root:root 1777              → MKDIR OK
/var/cache/nginx root:root 775   → MKDIR DENIED
```

Причина — `tmpfs: [/tmp, /var/cache/nginx]` під `read_only: true` (`docker-compose.yml:152-153`):
обидва монтуються root:root, але `/tmp` отримує 1777, а `/var/cache/nginx` — 775. Наслідок
редакції 1 («nginx не підніметься») правильний, фікс («іменований том із власником 101») —
ні. Правильний фікс — `/tmp`, і він же семантично коректний: кеш рішення на 30 с має бути
ефемерним.

**TTL кешу 30 с — це число з A32.** Воно ж — верхня межа вікна витіснення.

### D-3. Контракт `authorize` ⟵ C7

`GET /internal/playback/authorize`, заголовок `X-Video-Id`, куки `courseforge_session` і
`playback` → **204** дозволено, **403** ні. Тіла немає в обидва боки.

Політика трьох умов живе в `playback/application` ⟵ C5-конституційне; хендлер лише
перекладає транспорт.

Дозвіл = усі три:
1. сесійна кука дійсна;
2. **сесія логіну володіє слотом акаунта** (`playback:owner:{userId}` == id цієї сесії) ⟵ D-1;
3. відео `X-Video-Id` належить уроку **опублікованого** курсу — або актор адмін/власник (G2).

Відмова не розрізняється для клієнта (A7).

**Недоступність Redis або Postgres → 403** ⟵ C-defense-Q2. Симетрично й явно: перевірка,
яку неможливо виконати, — відмова.

**Недоступність Go: nginx мусить перетворити 5xx на 403 ⟵ C23.** `auth_request` трактує як
відмову **лише 401/403**; будь-що інше стає 500 для клієнта. Тому в `location ^~ /media/hls/`:

```
error_page 500 502 503 504 = @media_denied;
```
`location @media_denied { return 403; }` — двері й так зачинені, але **спостережуваний
критерій R11 стає правдою**, а не збігом.

### D-4. Володіння — Redis із compare-and-renew ⟵ C8, C14, C-defense-Q3

Ключ `playback:owner:{userId}` → `{sessionId}`, TTL = TTL доказу.

| Операція | Семантика | Реалізація |
|---|---|---|
| `play` без чинної куки | **витіснення**: безумовно забрати слот | `SET key newId EX ttl` |
| `play` сесією, що вже володіє | **ідемпотентно**: лише поновити ⟵ C14 | `SET` того самого значення — ідемпотентний і при паралельних викликах ⟵ D-Q3-1 |
| **`play` сесією, що НЕ володіє** ⟵ D-Q3-1 | **витіснення**, не 409: `play` завжди забирає слот | `SET key thisSession EX ttl` |
| heartbeat | поновити **тільки свій** ключ ⟵ C8 | Lua `EVAL`: `if GET==ARGV[1] then EXPIRE else return 0` |
| heartbeat не-власника | 409 `playback_taken_over` | те саме `EVAL` повертає 0 |

**Чому Lua, а не `EXPIRE`:** голий `EXPIRE` подовжив би **чужий** ключ, а наївний `SET EX`
старого власника повернув би володіння назад — пінг-понг кожні 30 с, який тихо знімає
гарантію G5. Атомарність тут не оптимізація, а сама гарантія.

**Ідемпотентність `play` ⟵ C14, D-Q3-1.** Оскільки значенням ключа тепер є **id сесії
логіну**, а не свіжозгенерований id, два паралельні `play` з того самого браузера пишуть
**однакове значення** — ідемпотентність випливає з форми даних, а не з блокування.

**`play` ніколи не відповідає 409 ⟵ D-Q3-1.** Редакція 2 мала лише два рядки й губила
випадок «сесія чинна, але слотом не володіє» — витіснений користувач, що повернувся на
перший пристрій. Наївний compare-and-renew дав би йому 409 і не пустив би до перегляду,
ламаючи A29/A33 і власні P13/B16. `play` — це **намір дивитися тут**, тож він завжди
забирає слот; 409 лишається виключно за heartbeat'ом.

### D-5. Тривалість і прогрес ⟵ C4, C15

**Тривалість персистить воркер.** `video_assets.duration_seconds numeric NULL` заповнюється
в момент публікації з `SourceProbe.DurationSeconds` — воркер єдиний, хто величину має, а
ADR 004 забороняє API і SSR монтувати медіа, тож вичитати плейлист із Go не можна.

**Правило для «невідомої тривалості» ⟵ D-Q4.** Редакція 2 закривала лише гілку `NULL` і
лишала відкритою гіршу — **нуль**. Заміряно в коді: `parseProbe` відкидає відʼємне, NaN та
Inf, але **нуль приймає** (`ffmpeg/transcoder.go:198-202`), а `AcceptSource` тривалість не
перевіряє **взагалі** (`domain/source.go:40-46`); `< 1` на рядку 167 — лише вибір позиції
seek для тумбнейла. Отже `duration_seconds = 0` досяжна, і правило `position >= 0.95 * 0`
позначало б **кожен урок переглянутим на нульовій секунді** — рівно та поломка, яку D-5
оголошувала усуненою.

**Тому невідомою вважається `NULL` І `<= 0`**, а воркер **не персистить** непридатну
величину: `duration <= 0` записується як `NULL`, а не як нуль. Невідома тривалість →
завершення не обчислюється, позиція зберігається й **не обрізається**.

`lesson_progress(user_id, lesson_id, position_seconds, completed_at, client_seq, updated_at)`,
PK `(user_id, lesson_id)`.

**Монотонність за `client_seq`, не за позицією ⟵ C15.** Запис приймається лише якщо
`client_seq > збереженого`. Це пропускає навмисне перемотування назад (свіжіший лічильник) і
відкидає протухлий офлайн-повтор, який інакше відмотав би студента.

**Лічильник засівається з сервера ⟵ D-Q3-2 — без цього фіча мовчки не працює.** У редакції 2
лічильник зростав «у межах сесії перегляду», а порівнювався з рядком `lesson_progress`, який
**сесію переживає**. Друга сесія на тому самому уроці стартувала б із нуля, і **кожен її
запис відкидався б як протухлий**, доки лічильник не перевищив би старий — за каденцією B10
це близько 4.5 хвилини відтворення без жодного збереження. Найгірше, що це **тихо**: P04/P05
перевіряють лише читання й лишились би зеленими.

Тому `client_seq` віддається читальною моделлю (D-6), плеєр засіває ним свій лічильник, і
рядок B29 спостерігає саме другу сесію.

`completed_at` ставиться при `duration_seconds IS NOT NULL AND position >= 0.95 * duration`
і **не знімається** ніколи, зокрема при заміні відео (G13). Обрізання позиції — **на
читанні**, до тривалості поточної генерації.

### D-6. Читальна модель навчання

`GET /api/v1/learn/courses/{slug}` (автентифіковано) → курс, модулі, уроки з id, стан відео,
позиція, позначка переглянутого. Один запит на вхід у курс.

Відповідь несе `clientSeq` кожного уроку ⟵ D-Q3-2 — інакше друга сесія не має чим засіяти
лічильник.

**Відсутній рядок прогресу ⟵ C-defense-Q4** — це `position: 0, completed: false, clientSeq: 0`,
а не `null` і не відсутнє поле. Це стан **усього продакшена в момент викатки**, тож він у
контракті, а не в припущенні.

Публічний `GET /api/v1/courses/{slug}` **не змінюється**.

Шлях до `master.m3u8` віддається цим же ендпоїнтом як поле ⟵ C26, а не збирається клієнтом
за конвенцією.

### D-7. Плеєр і проба AV1 ⟵ C9, C19, C30

**Порядок ініціалізації зафіксовано ⟵ C9.** hls.js монтується **без джерела**. Натискання
`play` → `POST /api/v1/playback/sessions` (мінт куки) → **тільки потім** `loadSource()`.
У редакції 1 `loadSource()` стріляв при монтуванні, тобто **перший запит кожного перегляду
був би 403** і fatal `NETWORK_ERROR` — система не стартувала б із порожнього стану.

**Два рушії, розподіл рядків ⟵ C30:** hls.js там, де `MediaSource` є; нативний HLS у Safari.
Ручний вибір якості (A12) належить **лише** гілці hls.js — у нативній його немає; це
записано, а не замовчано.

**Проба AV1 їде полем у тілі `play` ⟵ C19.** `MediaSource.isTypeSupported('video/mp4; codecs="av01…"')`
кладеться в тіло мінту сесії; Go інкрементує метрику. Нового каналу «браузер → Go» не
заводимо — спека §4 виносить обсервабельність фронту в беклог B-1, і план її не порушує.

### D-8. Один ендпоїнт замість двох ⟵ C31

Heartbeat і запис прогресу мають ту саму каденцію 30 с, того самого актора й той самий урок.
Отже це **один** `POST /api/v1/playback/heartbeat` із позицією в тілі: він і поновлює
володіння, і пише прогрес, і повертає 409 при витісненні.

**409 не скасовує запис позиції ⟵ D-Q3-3.** Витіснення стосується **права грати далі**, а не
правдивості того, що вже переглянуто: студент справді додивився до цієї секунди. Тому
порядок жорсткий — **спершу записати прогрес, потім відповісти 409**. Інакше витіснення
крало б у людини хвилини перегляду, і B18 (втрата звʼязку) поводилась би інакше, ніж
витіснення, без жодної причини.

## 5. План міграції ⟵ C4, C11, C24, C28

`00006_playback.sql` — **не лише додавання таблиці**, і редакція 1 тут була неправдива:

1. `CREATE TABLE lesson_progress` з FK на `users(id)` і **`course_lessons(id)`** ⟵ C11 —
   таблиці `lessons` не існує (`00003_authoring.sql:35`), Phase 5 посилається саме на
   `course_lessons` (`00005_media.sql:6`). Міграція редакції 1 не застосувалась би.
   **Обидва FK — `ON DELETE CASCADE`, і це не косметика ⟵ C-FK:** `deleteMissingAuthoringLessons`
   видаляє рядки `course_lessons` при **кожному** збереженні курсу
   (`course/adapters/postgres/authoring.go:237`), тож FK без `ON DELETE` дав би порушення на
   першому ж редагуванні курсу, у якого вже є прогрес.
2. `ALTER TABLE video_assets ADD COLUMN duration_seconds numeric NULL` ⟵ C4.

Окремого індексу `(user_id)` немає ⟵ C28 — PK `(user_id, lesson_id)` його вже покриває
префіксом.

**Бекфіл не потрібен і не робиться:** `NULL` — легальний стан із названим правилом (D-5).
Уже опубліковані асети лишаються без тривалості, доки їх не перезалито.

`down` — за конвенцією репо «Down is test-only» (`00005_media.sql:1-2`) ⟵ C24.

**Канарка:** міграція над заповненою базою і тест відкоту, за зразком B07/B08 Phase 5.

## 6. Rollback

_Пережив критику; уточнено одне речення._

| Крок | Як відкотити | Що лишиться |
|---|---|---|
| Edge | повернути `location ^~ /media/ { return 403; }` | нічого; перегляд зникає |
| Go, **media-worker**, фронт ⟵ D-Q5 | відкотити образи; воркер називається окремо, бо він **єдиний писар** `duration_seconds` | таблиця лишається й не заважає |
| Схема | `DROP TABLE lesson_progress`, `DROP COLUMN duration_seconds` | **дві незворотні втрати, не одна ⟵ D-Q5**: прогрес, і тривалості, які виробляє лише воркер і які лікуються **тільки перезаливом кожного відео**. `down` тестовий, тож у проді це ручний хід із свідомим рішенням |
| Redis | ключі мають TTL | самоочищується |

**Найдешевший аварійний хід — відкотити лише edge:** вимикає перегляд, не чіпає даних.

## 7. Конституція ⟵ C1-конституційне, C2, C3, §7-slop

Редакція 1 подавала цю секцію як самоатестацію. Тепер кожен рядок вказує на **машинний
гейт** або на артефакт, а не переказує намір.

| Правило | Чим доводиться |
|---|---|
| Напрямок залежностей backend | `backend/platform/architecture/boundaries_test.go` |
| Напрямок залежностей frontend | `frontend/scripts/check-architecture.mjs` |
| Контракт не дрейфує ⟵ C4-конституційне | `make check-generated`; нові ендпоїнти йдуть в `backend/openapi/openapi.yaml`, клієнт — через Orval |
| Домен без фреймворків, порти на справжні залежності | boundaries-тест + рев'ю: два порти (Redis, Postgres), **третій «читання курсу» знято** ⟵ C29 — читальна модель джойнить напряму (§1) |
| Байти не крізь Go і SSR | ADR 004 «API and SSR get no media mount» лишається; R22 |
| Строгий TS, a11y, теми, 200% | `make typecheck`, `make lint`, axe в unit, `frontend/e2e/accessibility.spec.ts` |
| Явні бізнес-коди | `playback_forbidden`, `playback_taken_over`, `lesson_not_found`, `video_not_ready` |

**Три конституційні blocking редакції 1 закриті так:**

- **C1 — поведінка HTTP range.** ADR 005 вимагає врегулювати її до ввімкнення медіа.
  **Рішення:** сегменти віддаються статикою, і nginx обслуговує range нативно; вимикати
  `Accept-Ranges` не треба, бо нативний HLS у Safari на нього спирається. Ключ кешу
  авторизації **не містить `Range`** — інакше кожен байтовий діапазон породжував би окремий
  запит до Go. Приймальні рядки: B20, B21.
- **C2 — G1 суперечить ADR 005** («Go checks session/enrollment»). Пишемо **ADR 010**, який
  уточнює ADR 005: предикат тимчасово «автентифікований + опублікований», шов незмінний,
  enrollment підставляється у Phase 8. Це таск ADR-1.
- **C3 — `AGENTS.md` містить два хибних твердження** (рядок скоупу «Current delivery: Phase 5»
  і «Foundation media access is denied until authorization exists»). Правляться в межах фази,
  як у Phase 5 правився мід-фазово (plan §23). Це таск DOC-1.
