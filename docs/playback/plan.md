## 3. Рішення дизайну

Конфіг edge нижче **не припущений, а виміряний** — спайк `spike-edge.md`, робочий файл
`spike-edge.conf`. Кожен рядок, помічений ✅, пройшов запуск.

### D-1. Сесія відтворення, її id — у префіксі шляху ⟵ спайк, C6-r3, D-Q3-1, D-Q3-2

**Ні куки, ні `user_sessions.id`.** Обидві попередні спроби провалились із однієї причини:
носій був **спільним для браузера**, а розрізняти треба **контекст відтворення**. Дві
вкладки ділять і куки, і сесію логіну — тож жодне з них не могло розрізнити їх у принципі.

На `play` Go створює сесію відтворення: 128-бітний випадковий `playbackId` (32 hex),
`playback:session:{id}` → `{userId, videoId, lessonId}` з TTL `ownershipTTL` (дефолт 180 с),
і **безумовно** пише `playback:owner:{userId} = playbackId`.

Відповідь несе шлях цілком, а не конвенцію ⟵ C26:
`/media/p/<playbackId>/hls/<videoId>/master.m3u8`.

Чому це закриває три blocking одразу:

| Було | Чому ламалось | Тепер |
|---|---|---|
| дві вкладки грають разом | кука/сесія спільні для браузера | два `play` → два `playbackId` → другий витісняє перший |
| `user_sessions.id` недосяжний (`Actor{UserID,Role}`) | його не селектить `ResolveIdentitySession` | не потрібен: id видає Go |
| сирий токен у файлі кеша | ключем була сесійна кука | ключ — `playbackId\|videoId`, ✅ перевірено `strings` |

**Грант ADR 005 на 3 хвилини** — це TTL запису в Redis; heartbeat поновлює, тиша знімає.

**Відносні URL плейлиста самі лишаються під префіксом** ✅ — виконує вимогу ADR 005
«relative playlist URLs must retain credentials» без переписування плейлистів.

### D-2. Edge — конфіг, що піднявся ⟵ спайк

У блоці `http`:

```
limit_req_zone $binary_remote_addr zone=media:10m rate=120r/s;

# ✅ БЕЗ ЦИХ ТРЬОХ nginx НЕ СТАРТУЄ. proxy_cache_path змушує створити ВСІ зареєстровані
# temp-каталоги на старті; дефолти ведуть у /var/cache/nginx (root:root 775), а процес — 101.
# Продакшн живий лише тому, що кеша в ньому немає: його /var/cache/nginx порожній.
fastcgi_temp_path /tmp/fastcgi_temp;
uwsgi_temp_path   /tmp/uwsgi_temp;
scgi_temp_path    /tmp/scgi_temp;
proxy_temp_path   /tmp/proxy_temp;
client_body_temp_path /tmp/client_temp;

proxy_cache_path /tmp/nginx-auth levels=1 keys_zone=media_auth:1m
                 max_size=8m inactive=60s use_temp_path=off;

map $uri $playback_id {
  default "";
  "~^/media/p/(?<p>[0-9a-f]{32})/hls/" $p;
}
map $uri $media_video {
  default "";
  "~^/media/p/[0-9a-f]{32}/hls/(?<v>[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12})/" $v;
}
```

У `server`:

```
location ^~ /media/p/ {
  # НОСІЇ: обчислити ДО rewrite, бо rewrite змінює $uri, а map ліниві.
  set $pb  $playback_id;
  set $vid $media_video;
  if ($pb  = "") { return 403; }   # ✅ гард: кривий id відсікається БЕЗ звернення до Go
  if ($vid = "") { return 403; }

  auth_request /_media_auth;
  error_page 401 403     = @denied;        # ✅ 401 від Authenticate стає 403 (A7)
  error_page 500 502 504 = @unavailable;   # ✅ 503 у списку — самопосилання, не додавати

  limit_req zone=media burst=240 nodelay;
  add_header X-Content-Type-Options nosniff always;
  add_header Referrer-Policy strict-origin-when-cross-origin always;
  add_header X-Frame-Options DENY always;
  add_header Cache-Control "private, no-store" always;

  # ✅ лапки обовʼязкові: без них nginx читає {32} як межі блоку і конфіг не парситься
  rewrite "^/media/p/[0-9a-f]{32}/(.*)$" /$1 break;
  root /media;
}
location @denied      { return 403; }
location @unavailable { add_header Retry-After 1 always; return 503; }
location ^~ /media/   { return 403; }   # source/, thumbnails/, temporary/ закриті

location = /_media_auth {
  internal;
  set $api http://api:8080;          # ⟵ C22: літерал тримав би старий IP після заміни контейнера
  proxy_pass $api/internal/playback/authorize;
  proxy_pass_request_body off;
  proxy_set_header Content-Length "";
  proxy_set_header X-Playback-Id $pb;
  proxy_set_header X-Video-Id    $vid;
  proxy_ignore_headers Cache-Control Expires Set-Cookie;   # ✅ інакше кеш не вмикається
  proxy_cache media_auth;
  proxy_cache_key "$pb|$vid";        # ✅ секрету в ключі немає
  proxy_cache_valid 200 204 30s;
  proxy_connect_timeout 2s;          # ✅ 1s давав 2% хибних відмов під навантаженням
  proxy_read_timeout 5s;
}
```

**Виміряна матриця статусів** ✅:

| Апстрім | Клієнт | Сенс |
|---|---|---|
| 204 | 200 | дозвіл |
| 403 | 403 | відмова |
| 401 | **403** | аноніма не відрізнити від не-власника (A7) |
| 500 | **503** | інфраструктура, ретраїбельно |
| недоступний | **503** | те саме |
| кривий id | 403 | гард, Go не турбують |

**Навантаження** ✅: 400 запитів, 20 паралельно, холодні ключі — **400 × 200**. З таймаутами
редакції 3 (`1s`/`2s`) той самий тест давав 8 × 403 при живому апстрімі.

**Один `authorize` покриває всі файли відео** ✅ — ключ це `(playback, video)`, не файл.

### D-3. Контракт `authorize` ⟵ C2-r3, D-Q2

`GET /internal/playback/authorize`, заголовки `X-Playback-Id`, `X-Video-Id`, сесійна кука.

Політика живе в `playback/application`; хендлер перекладає транспорт.

**204** тоді й лише тоді, коли всі три:
1. сесійна кука дійсна;
2. `playback:session:{id}` існує, його `userId` збігається з актором, його `videoId`
   збігається з `X-Video-Id`, і `playback:owner:{userId}` == цей `playbackId`;
3. відео належить уроку **опублікованого** курсу — або актор адмін чи власник курсу (G2).

**403** — будь-яка з трьох не виконана; клієнт не розрізняє яка (A7).

**503, а не 403, коли перевірку неможливо виконати** ⟵ уточнення G8. Redis чи Postgres
недоступні → Go віддає 503 → edge віддає 503. Це **так само fail-closed** (жодного байта не
видано), але чесніше: 403 каже «права немає», а насправді ми не знаємо. Спайк показав, що
відділення інфраструктури від відмови усуває 2% хибних термінальних відмов.

### D-4. Володіння ⟵ C8, C14, D-Q3-1, D-Q3-3

| Операція | Семантика | Реалізація |
|---|---|---|
| `play` | **завжди забирає слот** | `SET playback:owner:{userId} <new> EX ttl` |
| два паралельні `play` з однієї вкладки | обидва створюють сесії; виграє останній | нешкідливо: та сама вкладка одразу вживає свій `playbackId` |
| heartbeat власника | поновити **тільки свій** | Lua `EVAL`: `if GET==ARGV[1] then EXPIRE ... else return 0` |
| heartbeat не-власника | 409 `playback_taken_over` | той самий `EVAL` повертає 0 |
| **logout** ⟵ C8-r3 | зняти володіння **негайно** | `DEL playback:owner:{userId}` + `DEL playback:session:{id}` у тій самій операції, що й `logout` |

**`play` ніколи не 409** ⟵ D-Q3-1: витіснений, що повернувся на свій пристрій, мусить
могти грати. 409 лишається виключно за heartbeat.

**Logout закриває дірку, якої план не бачив три редакції** ⟵ C8-r3: без нього браузер після
виходу отримував би байти до 180 с. Лишається залишкове вікно кеша edge (≤30 с) — воно
назване в §9, а не замовчане.

### D-5. Тривалість і прогрес ⟵ C4, C10-r3, D-Q1, D-Q4

**Тривалість персистить воркер** у момент публікації: `video_assets.duration_seconds numeric NULL`.
**Непридатна величина не персистить взагалі** — `duration <= 0` пишеться як `NULL`.
Заміряно, що нуль досяжний: `parseProbe` відкидає відʼємне/NaN/Inf, але **нуль приймає**
(`ffmpeg/transcoder.go:198-202`), а `AcceptSource` тривалість не перевіряє
(`domain/source.go:40-46`).

`lesson_progress(user_id, lesson_id, position_seconds, completed_at, client_seq bigint, updated_at)`,
PK `(user_id, lesson_id)`.

**`completed_at` ставиться тільки на періодичному тіку** ⟵ C10-r3. Тіло heartbeat несе
`reason: tick | pause | seek | hide | nav | restore`, і завершення обчислюється **лише для
`tick`**. Інакше спрацьовував тихий баг: позиція 94/100, відео замінили на 90 с, читання
обрізає до 90/90, відновлювальний seek сам є подією запису — і урок ставав «переглянутим»,
хоча ніхто нічого не дивився.

**Монотонність за `client_seq`, засіяним із сервера** ⟵ C15, D-Q3-2. Читальна модель (D-6)
віддає збережений `client_seq`; плеєр засіває ним лічильник. Без засіву друга сесія на тому
самому уроці стартувала б із нуля й **не писала б нічого ~4.5 хв** — тихо, бо тести на це
лише читають.

**Верхня межа** ⟵ D-Q1: `client_seq` — `bigint`, приймається лише `0 <= seq <= 2^31`;
більше — 400, а не 500. Інакше одне велике число назавжди замуровує пару `(user, lesson)`.

**Обрізання позиції — на читанні**, до тривалості поточної генерації.

### D-6. Читальна модель навчання ⟵ C26, D-Q4, C11-r3

`GET /api/v1/learn/courses/{slug}` (автентифіковано) → курс, модулі, уроки з id, стан відео,
позиція, позначка переглянутого, **`clientSeq`** і **`continueLessonId`**.

Відсутній рядок прогресу — це `position: 0, completed: false, clientSeq: 0`, а не `null`.
Це стан усього продакшена в момент викатки.

Предикат видимості — **той самий**, що умова 3 в D-3, одним посиланням, а не другою копією.

### D-7. Плеєр ⟵ C9, C30, C-slop-P12

**Порядок ініціалізації несучий, і причина названа правильно** ⟵ C5-r3. hls.js монтується
**без джерела**, бо шлях до плейлиста **невідомий до мінту**: він містить `playbackId`.
`play` → `POST /playback/sessions` → `loadSource(відповідь.mediaPath)`. У редакції 3 цей
порядок обґрунтовувався скасованою кукою — виконавець законно прибрав би крок.

**Дві гілки** ⟵ C30: hls.js там, де є `MediaSource`; нативний HLS у Safari. Ручний вибір
якості (A12) належить **лише** гілці hls.js.

**Проба AV1 — один раз на завантаження сторінки** ⟵ C-slop-P12, а не на кожен `play`:
інакше повернення слота (B31) рахувало б сесію двічі й `P12` був би нестабільним.

### D-8. Один ендпоїнт heartbeat + прогрес ⟵ C31, D-Q3-3

`POST /api/v1/playback/heartbeat` із `{playbackId, positionSeconds, clientSeq, reason}`.
Поновлює володіння, пише прогрес, повертає 409 при витісненні.

**Порядок жорсткий: спершу записати прогрес, потім відповісти 409.** Витіснення стосується
права грати далі, а не правдивості вже переглянутого.

**Після 409 клієнт припиняє писати** ⟵ C7-r3 — саме це, а не серверна перевірка, усуває
двох паралельних писарів, яких редакція 3 створювала сама. Витіснений плеєр зупинено (G5),
тож писати йому вже нічого.

## 5. План міграції ⟵ C4, C11, C24, C28

`00006_playback.sql` — **не лише додавання таблиці**, і редакція 1 тут була неправдива:

1. `CREATE TABLE lesson_progress` з FK на `users(id)` і **`course_lessons(id)`** ⟵ C11 —
   таблиці `lessons` не існує (`00003_authoring.sql:35`), Phase 5 посилається саме на
   `course_lessons` (`00005_media.sql:6`). Міграція редакції 1 не застосувалась би.
   **Обидва FK — `ON DELETE CASCADE`, і це не косметика ⟵ C-FK:** `deleteMissingAuthoringLessons`
   видаляє рядки `course_lessons` при **кожному** збереженні курсу
   (`course/adapters/postgres/authoring.go:237`), тож FK без `ON DELETE` дав би порушення на
   першому ж редагуванні курсу, у якого вже є прогрес.
2. `ALTER TABLE video_assets ADD COLUMN duration_seconds numeric NULL` ⟵ C4.

Окремого індексу `(user_id)` немає ⟵ C28 — PK `(user_id, lesson_id)` його вже покриває
префіксом.

**Бекфіл не потрібен і не робиться:** `NULL` — легальний стан із названим правилом (D-5).
Уже опубліковані асети лишаються без тривалості, доки їх не перезалито.

`down` — за конвенцією репо «Down is test-only» (`00005_media.sql:1-2`) ⟵ C24.

**Канарка:** міграція над заповненою базою і тест відкоту, за зразком B07/B08 Phase 5.

## 6. Rollback

_Пережив критику; уточнено одне речення._

| Крок | Як відкотити | Що лишиться |
|---|---|---|
| Edge | повернути `location ^~ /media/ { return 403; }` | нічого; перегляд зникає |
| Go, **media-worker**, фронт ⟵ D-Q5 | відкотити образи; воркер називається окремо, бо він **єдиний писар** `duration_seconds` | таблиця лишається й не заважає |
| Схема — **тільки після відкоту воркера** ⟵ D-Q5 | `DROP COLUMN` при живому новому воркері ламає публікацію кожного наступного відео, бо він пише в неї. Порядок: воркер → API → схема. Далі `DROP TABLE lesson_progress`, `DROP COLUMN duration_seconds` | **дві незворотні втрати, не одна ⟵ D-Q5**: прогрес, і тривалості, які виробляє лише воркер і які лікуються **тільки перезаливом кожного відео**. `down` тестовий, тож у проді це ручний хід із свідомим рішенням |
| Redis | ключі мають TTL | самоочищується |

**Найдешевший аварійний хід — відкотити лише edge:** вимикає перегляд, не чіпає даних.

## 7. Конституція ⟵ C1-конституційне, C2, C3, §7-slop

Редакція 1 подавала цю секцію як самоатестацію. Тепер кожен рядок вказує на **машинний
гейт** або на артефакт, а не переказує намір.

| Правило | Чим доводиться |
|---|---|
| Напрямок залежностей backend | `backend/platform/architecture/boundaries_test.go` |
| Напрямок залежностей frontend | `frontend/scripts/check-architecture.mjs` |
| Контракт не дрейфує ⟵ C4-конституційне | `make check-generated`; нові ендпоїнти йдуть в `backend/openapi/openapi.yaml`, клієнт — через Orval |
| Домен без фреймворків, порти на справжні залежності | boundaries-тест + рев'ю: два порти (Redis, Postgres), **третій «читання курсу» знято** ⟵ C29 — читальна модель джойнить напряму (§1) |
| Байти не крізь Go і SSR | ADR 004 «API and SSR get no media mount» лишається; R22 |
| Строгий TS, a11y, теми, 200% | `make typecheck`, `make lint`, axe в unit, `frontend/e2e/accessibility.spec.ts` |
| Явні бізнес-коди | `playback_forbidden`, `playback_taken_over`, `lesson_not_found`, `video_not_ready` |

**Три конституційні blocking редакції 1 закриті так:**

- **C1 — поведінка HTTP range.** ADR 005 вимагає врегулювати її до ввімкнення медіа.
  **Рішення:** сегменти віддаються статикою, і nginx обслуговує range нативно; вимикати
  `Accept-Ranges` не треба, бо нативний HLS у Safari на нього спирається. Ключ кешу
  авторизації **не містить `Range`** — інакше кожен байтовий діапазон породжував би окремий
  запит до Go. Приймальні рядки: B20, B21.
- **C2 — G1 суперечить ADR 005** («Go checks session/enrollment»). Пишемо **ADR 010**, який
  уточнює ADR 005: предикат тимчасово «автентифікований + опублікований», шов незмінний,
  enrollment підставляється у Phase 8. Це таск ADR-1.
- **C3 — `AGENTS.md` містить два хибних твердження** (рядок скоупу «Current delivery: Phase 5»
  і «Foundation media access is denied until authorization exists»). Правляться в межах фази,
  як у Phase 5 правився мід-фазово (plan §23). Це таск DOC-1.

## 8. Приймальні сценарії

Переписано після третього GATE 2 і спайку. **Рядків: 82. Ручних: 0.** Рядки, помічені ✅, мають **виміряне** очікування, а не припущене.

**Рівні названо правильно ⟵ C12.** `infrastructure/tests/integration.sh:26-34` монтує **лише
`backend/`** і ганяє Go-тести з testcontainers — **nginx там не існує**. Тому всі edge-твердження
йдуть у `smoke.sh` (розширюється ⟵ C37), а не в `integration`.

**Smoke сам кладе фікстуру на том ⟵ C-smoke.** `Makefile:54` ставить `smoke` **перед** `e2e`,
тобто в момент smoke на томі немає жодного HLS-байта, і edge-рядки не мали б що спостерігати.
Тому smoke спершу кладе мінімальну фікстуру — один `master.m3u8`, один медіа-плейлист і один
сегмент — під відомим uuid. Це дешевше за зміну порядку гейтів і не залежить від того, чи
e2e встиг щось завантажити.

## 9. Реєстр ризиків ⟵ C40

| Ризик | Наслідок | Прийнято, бо |
|---|---|---|
| Redis критичний для перегляду | падіння Redis = перегляд недоступний | відмова безпечніша за пропуск (G8) |
| Go критичний для перегляду | падіння > 30 с = перегляд недоступний | коли Go лежить, SSR однаково не віддає сторінку |
| Тривалість зʼявляється лише в нових публікаціях | старі асети ніколи не позначаються переглянутими | правило `NULL` назване (D-5); перезалив лікує |
| Дві гілки плеєра | нативний Safari не має вибору якості | розподіл рядків названо (D-7) |
| Залишкове вікно кеша після logout | до 30 с браузер, що вийшов, ще може отримати сегмент | назване, не замовчане; скорочується лише зменшенням `proxy_cache_valid` |
| `playbackId` у URL | видимий у devtools і в історії | сам по собі доступу не дає: `auth_request` вимагає чинну сесійну куку |
