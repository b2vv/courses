## 3. Рішення дизайну

### D-1. Доказ доступу — короткоживуча кука, а не токен в URL

На `play` Go видає куку `playback` (`HttpOnly`, `Secure` коли зʼявиться TLS, `SameSite=Strict`,
`Path=/media`, TTL **3 хв** — усередині вимоги 2–5 хв). Вона несе непрозорий id сесії
перегляду (G10) і нічого більше.

Чому кука, а не URL: A37 (жоден доказ не в логах, зокрема в URL) виконується сам собою;
сценарій 2.5 (переслане посилання) ламається без жодної додаткової роботи, бо куки не
пересилаються разом із URL; і плеєру не треба переписувати URL сегментів усередині
плейлиста — плейлисти лишаються тими самими статичними файлами, які опублікувала Phase 5.

**Наслідок, який треба перевірити тестом:** `Path=/media` означає, що кука не летить у
`/api/*`. Продовження живе на окремому ендпоїнті, який читає **сесійну** куку, а не цю.

### D-2. Edge: `auth_request` із кешем

```
location ^~ /media/ {
  auth_request /_media_auth;      # 204 → віддати, 403 → відмовити
  limit_req zone=media burst=... nodelay;
  add_header Cache-Control "private, no-store" always;
  root /;                          # том змонтовано на /media:ro
}
location = /_media_auth {
  internal;
  proxy_pass http://api:8080/internal/playback/authorize;
  proxy_pass_request_body off;
  proxy_set_header Content-Length "";
  proxy_set_header X-Original-URI $request_uri;
  proxy_cache media_auth;          # ключ: playback-кука + id відео
  proxy_cache_valid 200 204 30s;
}
```

TTL кешу **30 с** — це і є число з A32. Воно назване тут, і саме воно, а не слово
«миттєво», їде в acceptance.

**Пастка, виміряна до написання плану, а не після.** Образ — `nginxinc/nginx-unprivileged`,
процес працює як `uid=101(nginx)`, і скомпільовані шляхи ведуть у `/var/cache/nginx`, який
для цього користувача **не записуваний**; записуваний `/tmp`. Перевірено:

```
$ docker compose run --rm --entrypoint sh nginx -c 'id; test -w /var/cache/nginx || echo no'
uid=101(nginx) gid=101(nginx)
not writable /var/cache/nginx
```

Сьогодні це непомітно: `proxy_temp` потрібен лише коли відповідь не влазить у буфери й
спливає на диск, а наш проксі стільки не віддає. Але **`proxy_cache_path` перевіряється на
старті** — nginx із незаписуваним шляхом не підніметься взагалі, і фаза впала б на першій же
викатці edge. Тому `proxy_cache_path` вказує в записуваний шлях (`/tmp/nginx-cache`, або
іменований том із власником 101), і **тест мусить довести, що nginx стартує з цим конфігом**,
а не лише що правило працює.

**`/internal/` не маршрутизується ззовні:** nginx проксіює лише `^~ /api/`, `^~ /uploads/`
і `/`. Ендпоїнт слухає на тому ж `:8080` всередині мережі. Тест мусить довести, що
`GET /internal/playback/authorize` крізь edge дає 404, а не 204.

### D-3. Контракт `authorize`

`GET /internal/playback/authorize` → **204** дозволено, **403** ні. Тіла немає в обидва боки.

Дозвіл = усі три разом:
1. сесійна кука дійсна (особа є);
2. `playback`-кука дійсна і **володіє** слотом акаунта (G3, G5);
3. відео з `X-Original-URI` належить уроку опублікованого курсу — **або** актор є адміном
   чи власником курсу (G2, A2).

Відмова **не розрізняється** для клієнта: 403 в усіх трьох випадках (A7).

### D-4. Володіння — Redis, витіснення записом

Ключ `playback:owner:{userId}` → `{sessionId}`, TTL 3 хв, поновлюється heartbeat'ом.
`play` **перезаписує** ключ безумовно — це і є витіснення (G4). Ніяких списків сесій: слот
один (G3), тож структура — один ключ, а не множина.

Витіснений клієнт дізнається двома шляхами: heartbeat отримує 409 (клієнтський стоп, G5) і
`authorize` перестає давати 204 щонайпізніше через 30 с (серверна гарантія, G5/A31/A32).

**Redis недоступний → `authorize` відповідає 403**, не 204 (G8, A10).

### D-5. Прогрес — Postgres, останній запис перемагає

`lesson_progress(user_id, lesson_id, position_seconds, completed_at, updated_at)`,
PK `(user_id, lesson_id)`, `UPSERT`. Злиття не потрібне: за G3 одночасний перегляд один,
тож конкурентних записів по одному ключу практично не буває.

`completed_at` ставиться при досягненні 95% (G11) і **не знімається** ніколи, зокрема при
заміні відео (G13). Позиція обрізається до тривалості поточної генерації **на читанні**, а
не на записі — інакше заміна відео вимагала б переписати всі рядки.

### D-6. Читальна модель студента

`GET /api/v1/learn/courses/{slug}` (автентифіковано) → курс, модулі, уроки **з id**, стан
відео кожного уроку, позиція й позначка переглянутого. Один запит на вхід у курс; зміст і
прогрес приходять разом, бо показуються разом (A19).

Публічний `GET /api/v1/courses/{slug}` **не змінюється**: він анонімний і навмисно без id.

### D-7. Плеєр

`hls.js` з нативним fallback на Safari (де HLS підтримано браузером). Плеєр споживає
`master.m3u8` як є. Проба можливостей AV1 (§24.17) — `MediaSource.isTypeSupported` на старті
сесії, результат іде в одну метрику й **нічого не вмикає** (A17).

| Сайд-ефект | Хто зачеплений | Помʼякшення |
|---|---|---|
| `/media/` перестає бути беззастережним 403 | edge, і це вся суть фази | R13 із Phase 5 (403 для всіх) **перестає бути істинним** і мусить бути переписаний, а не видалений: анонім і чужий далі отримують 403 |

| Навантаження на API зростає на heartbeat | Go | один запит на 30 с на глядача — того ж порядку, що поллінг Phase 5 |
| Нова таблиця в гарячому шляху | Postgres | `UPSERT` по PK; запис раз на 30 с на глядача |

## 5. План міграції

`00006_playback.sql` — **лише додавання**: нова таблиця `lesson_progress`, індекс
`(user_id)` для читання курсу, FK на `users(id)` і `lessons(id)` з `ON DELETE CASCADE`.

Наявні таблиці **не змінюються**. Отже міграція оборотна: `down` — `DROP TABLE`.

Порядок безпечний за будь-якої послідовності викатки: нова таблиця нікому не потрібна, поки
нема нового коду; новий код без таблиці не стартує, тому `migrate` іде першим, як і зараз
(`docker-compose.yml:39`).

**Канарка:** тест міграції над заповненою базою і тест відкоту, за зразком B07/B08 із
Phase 5 (`docs/media/report.md`).

## 6. Rollback

| Крок | Як відкотити | Що лишиться |
|---|---|---|
| Edge | повернути `location ^~ /media/ { return 403; }` — один блок | нічого; перегляд просто зникає |
| Go | відкотити образ | таблиця лишається порожньою й нікому не заважає |
| Міграція | `DROP TABLE lesson_progress` | втрачається прогрес — **єдина незворотна втрата фази**; тому відкат схеми робиться лише разом із рішенням «прогрес не потрібен» |
| Redis | ключі мають TTL 3 хв | самоочищується |
| Фронт | відкотити образ | `/learn` повертається до порожнього стану |

**Найдешевший аварійний хід — відкотити лише edge.** Він вимикає перегляд, не чіпаючи
даних, і не потребує узгодження з рештою.

## 8. Приймальні сценарії

Складено делегуванням `acceptance-spec` 2026-09-07. Три групи: **P** — happy path,
**B** — межі, **R** — відмови. Кожен рядок — одне спостереження, сформульоване так, щоб
двоє людей однаково сказали, збіглося воно чи ні.

## 9. Задачі

_Заповнюється після GATE 2._

**Запропонований розріз із внутрішньою віхою.** Фазу не ділимо формально, але порядок
тасків такий, щоб на середині існував **працюючий продукт**: доступ + плеєр на мінімальному
маршруті уроку. Усе, що після віхи — зміст курсу, прогрес, витіснення — нарощується поверх
того, що вже грає. Це дає користь розрізу 6a/6b без перейменування фази і без узгодження
двох звітів.
