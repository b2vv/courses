**Що змінилось у редакції 5.** Одне рішення, від якого залежить решта: **кеша авторизації
немає**. Обидва рецензенти незалежно назвали причину, через яку ред. 3 і ред. 4 розбились об
нього з дзеркальних боків — *сутність несла дві функції, прибрали одну, загубили обидві*.
Ред. 3 поклала в ключ сесійну куку й записала секрет у файл; ред. 4 прибрала секрет і разом
із ним **особу**, після чого теплий ключ віддавав байти анонімові.

Кеш прибрано. Це закриває шість позицій одразу: ключ без особи, недосяжний `logout`,
залишкові вікна після виходу й архівації, вікно витіснення й секрет у файлі. Підстава —
власний замір спайку: 400 запитів на **холодних** ключах, кожен доходив до Go, усі 400 дали
200.

Решта: один ключ Redis замість двох (ред. 4 не поновлювала другий і вбивала перегляд на
180-й секунді); 409 і 410 розділені, тож пауза чи подвійний клік більше не термінальні;
завершення уроку спирається на **серверне** правило «позиція зросла», а не на клієнтське
поле; таблиця відновлення плеєра для 403/404/409/410/503, якої не було в жодній редакції.

Журнали знахідок: `work/report-critique-phase6{,-r2}.md`, `work/report-defense-phase6{,-r2}.md`.
Позначки: `⟵ Cnn` — критика, `⟵ D-Qn` — захист.

**Три речі, які не можна загубити при виконанні.** (1) Відеобайти не проходять крізь Go і
крізь SSR (`PRODUCT-BRIEF` §2 п.13–14). (2) Недоступність перевірки — **відмова**, ніколи не
пропуск (G8). (3) Витіснення мусить кусатись **на сервері**; клієнтський стоп — зручність (G5).

## 3. Рішення дизайну

**Одне рішення, від якого залежить решта: кеша авторизації немає.** Обидві попередні редакції
розбились об нього з дзеркальних боків — ред. 3 поклала в ключ сесійну куку й записала секрет
у файл; ред. 4 прибрала секрет і разом із ним **особу**, після чого теплий ключ віддавав байти
анонімові. Рецензент назвав механізм точно: сутність несла дві функції, прибрали одну —
загубили обидві.

Кеш прибрано цілком. Підстава не теоретична: у навантажувальному замірі спайку всі 400
запитів ішли на **холодних** ключах, тобто кожен доходив до Go, і всі 400 повернули 200.
Кеш там не рятував нічого.

### D-1. Сесія відтворення — ОДИН ключ, id у префіксі шляху ⟵ #4

`POST /api/v1/playback/sessions` (це і є `play`) створює `playbackId` — 128 біт випадкових,
32 hex — і пише **єдиний** запис:

```
playback:owner:{userId} = {playbackId, videoId, lessonId}   EX ownershipTtlSeconds
```

**Один ключ, а не два.** Ред. 4 заводила ще `playback:session:{id}` із власним TTL, який
**ніхто не поновлював**, — на 180-й секунді активний глядач діставав 403 на кожному сегменті.
Один ключ робить цей клас неможливим: поновлюється рівно те, що перевіряється.

Відповідь несе шлях цілком і параметри циклу:
`{playbackId, mediaPath, clientSeq, heartbeatSeconds, ownershipTtlSeconds}`.

**Інваріант, названий числом ⟵ #5:** `heartbeatSeconds * 3 <= ownershipTtlSeconds`
(дефолт 30 і 180). Він перевіряється при завантаженні конфігу — не домовленість, а гард.

### D-2. Edge — без кеша ⟵ #1, #2

```
limit_req_zone $binary_remote_addr zone=media:10m rate=120r/s;

map $uri $playback_id {
  default "";
  "~^/media/p/(?<p>[0-9a-f]{32})/hls/" $p;
}
map $uri $media_video {
  default "";
  "~^/media/p/[0-9a-f]{32}/hls/(?<v>[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12})/" $v;
}
```

```
location ^~ /media/p/ {
  set $pb  $playback_id;          # носій: map лінивий, rewrite змінює $uri
  set $vid $media_video;
  if ($pb  = "") { return 403; }  # ✅ гард: Go не турбують кривим id
  if ($vid = "") { return 403; }

  auth_request /_media_auth;
  error_page 401 403     = @denied;        # ✅ 401 від Authenticate стає 403 (A7)
  error_page 500 502 504 = @unavailable;   # ✅ 503 у списку — самопосилання

  limit_req zone=media burst=240 nodelay;
  add_header X-Content-Type-Options nosniff always;
  add_header Referrer-Policy strict-origin-when-cross-origin always;
  add_header X-Frame-Options DENY always;
  add_header Cache-Control "private, no-store" always;

  rewrite "^/media/p/[0-9a-f]{32}/(.*)$" /$1 break;   # ✅ лапки обовʼязкові
  root /media;
}
location @denied      { return 403; }
location @unavailable { add_header Retry-After 1 always; return 503; }
location ^~ /media/   { return 403; }

location = /_media_auth {
  internal;
  set $api http://api:8080;
  proxy_pass $api/internal/playback/authorize;
  proxy_pass_request_body off;
  proxy_set_header Content-Length "";
  proxy_set_header X-Playback-Id $pb;
  proxy_set_header X-Video-Id    $vid;
  proxy_connect_timeout 2s;       # ✅ 1s давав 2% хибних відмов під навантаженням
  proxy_read_timeout 5s;
}
```

**Чого тут більше немає.** Зникли `proxy_cache_path`, `proxy_cache`, `proxy_cache_key`,
`proxy_ignore_headers`. **Temp-шляхів це не стосується** — виправлення до спайку
(`spike-edge.md` §1): nginx створює їх на старті незалежно від кеша, і продакшн-конфіг уже
перенаправляє всі пʼять у `/tmp` (`infrastructure/nginx/nginx.conf:8-12`). Тобто §3 нічого до
них не додає й нічого з них не прибирає.

### D-3. Контракт `authorize` — порядок умов несучий ⟵ #2, #3, #9

`GET /internal/playback/authorize`, заголовки `X-Playback-Id`, `X-Video-Id`, сесійна кука.

**204** тоді й лише тоді, коли всі три, і саме в цьому порядку:

| # | Умова | Вартість | Що відсікає |
|---|---|---|---|
| 1 | сесійна кука дійсна | Postgres, але це вже наявний шлях `Authenticate` | аноніма й **того, хто вийшов** |
| 2 | `playback:owner:{userId}` існує, його `playbackId` == `X-Playback-Id`, `videoId` == `X-Video-Id` | **Redis GET** | випадковий чи чужий `playbackId`, витіснений пристрій |
| 3 | відео належить уроку опублікованого курсу — або актор адмін/власник курсу | Postgres | неопублікований і чужий курс |

**Порядок — це і є відповідь на «неавтентифікований канал у Go» ⟵ #2.** Підібраний
`playbackId` помирає на умові 2, тобто на одному Redis-GET, не доходячи до бази. Разом із
`limit_req zone=media` це і є бюджет.

**`logout` більше не потребує механізму ⟵ #9.** Ред. 4 намагалась знімати володіння на
виході — і виявилось, що маршрут `logout` зареєстрований **без** `Authenticate`
(`identity/adapters/http/handler.go:71`), а `Revoke(ctx, token) error` користувача не
повертає. Без кеша це не потрібно: після виходу **умова 1 провалюється на першому ж
сегменті**. Правки завершеної Phase 2 не треба, забороненої залежності `identity → playback`
теж.

**Недоступна залежність → 503, і це записано в ОДНОМУ місці ⟵ #3.** Redis чи Postgres
недоступні — Go віддає 503, edge віддає 503. Це так само fail-closed: жодного байта. §4, §9
і рядки R11–R13 приведені до цього формулювання; у ред. 4 вони суперечили D-3.

### D-4. Володіння ⟵ #4, #6, #8

| Подія | Семантика | Реалізація |
|---|---|---|
| `play` | **завжди забирає слот** | `SET playback:owner:{userId} {…} EX ttl` |
| heartbeat власника | поновити **тільки свій** | Lua `EVAL`: звірити `playbackId`, потім `EXPIRE` |
| heartbeat не-власника | **409** `playback_taken_over` | `EVAL` повернув 0, ключ існує з іншим id |
| heartbeat із невідомим/протухлим id | **410** `playback_session_expired` | ключа немає зовсім |

**409 і 410 — різні події, і плутати їх не можна ⟵ #8.** У ред. 4 обидві вели до зупинки
плеєра, тож пауза, довша за TTL, або подвійний клік **вбивали власний перегляд**. Тепер:
409 — «грають на іншому пристрої», плеєр зупиняється; 410 — «моя сесія протухла», плеєр
**мовчки мінтить нову** і грає далі.

**Пауза, довша за TTL, більше не термінальна ⟵ #6:** зняття з паузи проходить шлях 410 →
новий мінт.

### D-5. Тривалість і прогрес ⟵ #10, #11, #12, #13, #14

Тривалість персистить воркер; `duration <= 0` пишеться як `NULL` (нуль досяжний:
`parseProbe` його приймає, `AcceptSource` тривалість не перевіряє).

`lesson_progress(user_id, lesson_id, position_seconds, completed_at, client_seq bigint, updated_at)`,
PK `(user_id, lesson_id)`.

**Завершення не спирається на клієнтське поле ⟵ #11.** Ред. 4 захищалась полем `reason`, а
баг був серверний. Тепер правило суто серверне:

> `completed_at` ставиться, коли `duration_seconds > 0`, `position >= 0.95 * duration`
> **і `position > збереженої позиції`**.

Відновлювальний запис несе **ту саму** позицію, що збережена, тож завершити урок сам собою
не може — саме цей сценарій (94/100 → відео замінили на 90 с → seek відновлення) робив урок
«переглянутим» без перегляду.

**`reason` лишається інформаційним**, а `ended` додано до переліку ⟵ #10: тіки раз на 30 с
могли просто не влучити у вікно між 95% і кінцем.

**Позиція, більша за тривалість, обрізається на записі, а не відхиляється ⟵ #12.** Ред. 4
мала три несумісні правила (обрізання на читанні, поріг на записі, 400 на «більше за
тривалість»). Обрізання **одне**, і воно на записі; читання віддає збережене.

**Пише тільки власник ⟵ #14.** Витіснений пристрій отримує 409 і **не пише**: інакше він міг
відмотати студента назад більшим `client_seq`. Втрата — щонайбільше 30 с, бо попередній тік
уже записаний.

**Межа `client_seq` ⟵ #13:** приймається `0 <= seq < 2^31`; на межі — 400 і **вказівка
переcіятись** із читальної моделі, яка віддає збережене значення. Інакше одне велике число
замуровувало б пару `(user, lesson)` назавжди.

### D-6. Читальна модель навчання

`GET /api/v1/learn/courses/{slug}` → курс, модулі, уроки з id, стан відео, позиція,
позначка переглянутого, `clientSeq`, `continueLessonId`.

Відсутній рядок — це `position: 0, completed: false, clientSeq: 0`, не `null`.

Предикат видимості — **посилання** на умову 3 D-3, не друга копія.

### D-7. Плеєр і його відновлення ⟵ #7, E6

hls.js монтується без джерела: шлях невідомий до мінту, бо містить `playbackId`.
`play` → мінт → `loadSource(mediaPath)`.

**Таблиця відновлення — те, чого не було в жодній редакції:**

| Що сталось | Реакція плеєра |
|---|---|
| **403** посеред відтворення | один повторний мінт; якщо знову 403 — стан відмови, без циклу |
| **410** на heartbeat | мовчазний повторний мінт, відтворення триває |
| **409** на heartbeat | зупинка з «грають на іншому пристрої» |
| **404** на сегменті ⟵ E6 | **відео замінили**: `videoId` зашитий у префікс, стара генерація зникла з тому. Перечитати читальну модель і перезавантажити плеєр |
| **503** | ретрай із відступом; це не відмова |

**Дві гілки** лишаються: hls.js там, де є `MediaSource`; нативний HLS у Safari. Ручний вибір
якості (A12) — **лише** гілка hls.js; автовибір належить обом і покритий окремо ⟵ #19.

**Проба AV1 — один раз на завантаження сторінки**, не на кожен мінт: повторні мінти (410,
403) інакше рахували б сесію кілька разів.

### D-8. Heartbeat ⟵ #15

`POST /api/v1/playback/heartbeat` із `{playbackId, lessonId, positionSeconds, clientSeq, reason}`.

`lessonId` у тілі **обовʼязковий**: без нього запис прогресу не має адресата, коли запис у
Redis уже зник, і сервер віддавав би 409 неправдиво.

| Ситуація | Відповідь |
|---|---|
| власник | 204, прогрес записано |
| не-власник | **409** `playback_taken_over`, **без запису** |
| невідомий `playbackId` | **410** `playback_session_expired` |
| урок зник | **404** `lesson_not_found` |
| `clientSeq` поза межею | **400** |

| Медіашляхи стають персональними | у URL зʼявляється `playbackId`; сам по собі він доступу не дає — `auth_request` однаково вимагає чинну сесійну куку, тож витік посилання нічого не відкриває |
| Redis критичний для перегляду | недоступність = **503**, не 403 (D-3); fail-closed лишається — жодного байта |
| Heartbeat раз на 30 с на глядача | поллінг Phase 5 — раз на 3 с (`videoPollMs = 3_000`), тобто новий трафік **на порядок рідший** ⟵ C40 |
| `video_assets` отримує колонку | зачіпає шлях публікації Phase 5 — названо в §5 |

## 5. План міграції ⟵ C4, C11, C24, C28

`00006_playback.sql` — **не лише додавання таблиці**, і редакція 1 тут була неправдива:

1. `CREATE TABLE lesson_progress` з FK на `users(id)` і **`course_lessons(id)`** ⟵ C11 —
   таблиці `lessons` не існує (`00003_authoring.sql:35`), Phase 5 посилається саме на
   `course_lessons` (`00005_media.sql:6`). Міграція редакції 1 не застосувалась би.
   **Обидва FK — `ON DELETE CASCADE`, і це не косметика ⟵ C-FK:** `deleteMissingAuthoringLessons`
   видаляє рядки `course_lessons` при **кожному** збереженні курсу
   (`course/adapters/postgres/authoring.go:237`), тож FK без `ON DELETE` дав би порушення на
   першому ж редагуванні курсу, у якого вже є прогрес.
2. `ALTER TABLE video_assets ADD COLUMN duration_seconds numeric NULL` ⟵ C4, з явним
   **`lock_timeout`** ⟵ E-r4: воркер пише в цю таблицю безперервно, тож міграція без
   таймауту чекала б на блокування невизначено довго.

Окремого індексу `(user_id)` немає ⟵ C28 — PK `(user_id, lesson_id)` його вже покриває
префіксом.

**Бекфіл не потрібен і не робиться:** `NULL` — легальний стан із названим правилом (D-5).
Уже опубліковані асети лишаються без тривалості, доки їх не перезалито.

`down` — за конвенцією репо «Down is test-only» (`00005_media.sql:1-2`) ⟵ C24.

**Канарка:** міграція над заповненою базою і тест відкоту, за зразком B07/B08 Phase 5.

## 6. Rollback

_Пережив критику; уточнено одне речення._

| Крок | Як відкотити | Що лишиться |
|---|---|---|
| Edge | повернути `location ^~ /media/ { return 403; }` | нічого; перегляд зникає |
| Go, **media-worker**, фронт ⟵ D-Q5 | відкотити образи; воркер називається окремо, бо він **єдиний писар** `duration_seconds` | таблиця лишається й не заважає |
| Схема — **тільки після відкоту воркера** ⟵ D-Q5 | `DROP COLUMN` при живому новому воркері ламає публікацію кожного наступного відео, бо він пише в неї. Порядок: воркер → API → схема. Далі `DROP TABLE lesson_progress`, `DROP COLUMN duration_seconds` | **дві незворотні втрати, не одна ⟵ D-Q5**: прогрес, і тривалості, які виробляє лише воркер і які лікуються **тільки перезаливом кожного відео**. `down` тестовий, тож у проді це ручний хід із свідомим рішенням |
| Redis | ключі мають TTL | самоочищується |

**Найдешевший аварійний хід — відкотити лише edge:** вимикає перегляд, не чіпає даних.

## 7. Конституція ⟵ C1-конституційне, C2, C3, §7-slop

Редакція 1 подавала цю секцію як самоатестацію. Тепер кожен рядок вказує на **машинний
гейт** або на артефакт, а не переказує намір.

| Правило | Чим доводиться |
|---|---|
| Напрямок залежностей backend | `backend/platform/architecture/boundaries_test.go` |
| Напрямок залежностей frontend | `frontend/scripts/check-architecture.mjs` |
| Контракт не дрейфує | `make check-generated` для **публічних** ендпоїнтів (`/api/v1/learn/*`, `/api/v1/playback/*`). **Внутрішній `authorize` він не бачить** ⟵ #16 — його поведінку пінують контрактні тести хендлера й smoke-рядки R11–R13, B36, і це названо, а не видано за покриття |
| Домен без фреймворків, порти на справжні залежності | boundaries-тест + рев'ю: два порти (Redis, Postgres), **третій «читання курсу» знято** ⟵ C29 — читальна модель джойнить напряму (§1) |
| Байти не крізь Go і SSR | ADR 004 «API and SSR get no media mount» лишається; R22 |
| Строгий TS, a11y, теми, 200% | `make typecheck`, `make lint`, axe в unit, `frontend/e2e/accessibility.spec.ts` |
| Явні бізнес-коди | `playback_forbidden`, `playback_taken_over`, `lesson_not_found`, `video_not_ready` |

**Три конституційні blocking редакції 1 закриті так:**

- **C1 — поведінка HTTP range.** ADR 005 вимагає врегулювати її до ввімкнення медіа.
  **Рішення:** сегменти віддаються статикою, і nginx обслуговує range нативно; вимикати
  `Accept-Ranges` не треба, бо нативний HLS у Safari на нього спирається. Ключ кешу
  авторизації **не містить `Range`** — інакше кожен байтовий діапазон породжував би окремий
  запит до Go. Приймальні рядки: B20, B21.
- **C2 — G1 суперечить ADR 005** («Go checks session/enrollment»). Пишемо **ADR 010**, який
  уточнює ADR 005: предикат тимчасово «автентифікований + опублікований», шов незмінний,
  enrollment підставляється у Phase 8. Це таск ADR-1.
- **C3 — `AGENTS.md` містить два хибних твердження** (рядок скоупу «Current delivery: Phase 5»
  і «Foundation media access is denied until authorization exists»). Правляться в межах фази,
  як у Phase 5 правився мід-фазово (plan §23). Це таск DOC-1.

## 8. Приймальні сценарії

Переписано після четвертого GATE 2. **Рядків: 94. Ручних: 0.** Рядки, помічені ✅, мають **виміряне** очікування, а не припущене.

**Рівні названо правильно ⟵ C12.** `infrastructure/tests/integration.sh:26-34` монтує **лише
`backend/`** і ганяє Go-тести з testcontainers — **nginx там не існує**. Тому всі edge-твердження
йдуть у `smoke.sh` (розширюється ⟵ C37), а не в `integration`.

**Smoke сам кладе фікстуру на том ⟵ C-smoke.** `Makefile:54` ставить `smoke` **перед** `e2e`,
тобто в момент smoke на томі немає жодного HLS-байта, і edge-рядки не мали б що спостерігати.
Тому smoke спершу кладе мінімальну фікстуру — один `master.m3u8`, один медіа-плейлист і один
сегмент — під відомим uuid. Це дешевше за зміну порядку гейтів і не залежить від того, чи
e2e встиг щось завантажити.

## 9. Реєстр ризиків ⟵ C40

| Ризик | Наслідок | Прийнято, бо |
|---|---|---|
| Redis критичний для перегляду | падіння Redis = перегляд недоступний | відмова безпечніша за пропуск (G8) |
| Go критичний для перегляду, **без буфера** | будь-яке падіння Go зупиняє перегляд одразу — кеша, що згладжував би 30 с, більше немає | свідомий обмін: кеш коштував ідентичності в ключі. Коли Go лежить, SSR однаково не віддає сторінку уроку |
| Тривалість зʼявляється лише в нових публікаціях | старі асети ніколи не позначаються переглянутими | правило `NULL` назване (D-5); перезалив лікує |
| Дві гілки плеєра | нативний Safari не має вибору якості | розподіл рядків названо (D-7) |
| `playbackId` у URL | видимий у devtools і в історії | **тепер це правда без застережень**: без кеша сесійна кука перевіряється на кожному запиті, тож саме посилання не відкриває нічого. У ред. 4 те саме твердження було хибним для теплого ключа |
| Перегляд у момент заміни відео | сегмент старої генерації дає 404 | плеєр перечитує читальну модель (D-7); рядок B40 |
