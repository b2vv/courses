## Проблема

Редактор уроку (`/admin/courses/{id}/lessons/{id}`) і reader (`/learn/{slug}/{lessonId}`) функціонально
повні й типізовано-секційні, але **візуально голий MVP**. Конкретно (перевірено живою проходкою
2026-10-13):

- **Автор не бачить меж того, що редагує.** Секції зливаються в щільний вертикальний стек без карток,
  рамок і відступів; редагований rich-text схожий на звичайний підпис; зона вводу не має видимої площі
  чи фокус-ринга. Три секції на екрані невідрізнювані одна від одної.
- **Усі рівні дій важать однаково.** Save/Publish, впорядкування секції, форматування, додавання колонки
  й додавання секції стоять щільно поруч однаковою вагою; тип секції — звичайний span; палітри додавання
  без видимого підпису. Автор не читає ієрархію операцій.
- **Зображення — сирий HTML.** Нативний `<input type=file>` з позлипаними підписами («Upload imageChoose
  file No file chosen»), alt-поле губиться, preview без обмеження шириною. Поруч у kit є готові
  доступні поля, не вжиті.
- **Форматування без видимого активного стану.** Кнопки Bold/Italic/Heading/List виставляють
  `aria-pressed`, але він не стилізований — автор не бачить, яка марка активна.
- **Reader-документ програє службовим блокам.** Прозовий матеріал і завдання — два непримітні рядки,
  тоді як сусідні Transcript/Discussion і порожній player доглянутіші; немає ритму p/h2/h3/списків,
  оформлення посилань, обмеження довжини рядка; завдання (task) не має власного вигляду чи підпису.
- **Поведінка приховує результат і втрачає роботу.** Save/Publish не показують, що саме сталося (лише
  локальне/збережено/опубліковано); `upload.isPending` спільний для всіх зображень; невалідний URL тихо
  **видаляє** посилання й закриває поле без пояснення; після додавання/видалення/перестановки секції фокус
  не визначений.

Наслідок: автор не довіряє власним діям (не видно поля, межі, результату), а учень отримує матеріал, що
виглядає незавершеним. Spec lesson-builder прямо лишив повний дизайн-прохід на майбутнє — ця фаза його
започатковує в межах наявної секційної моделі, **без** нової взаємодії (drag) чи зміни даних.

## Користувацькі сценарії

1. **Автор оформлює урок.** Відкриває редактор, бачить кожну секцію як чітко окреслений блок із підписом
   типу, згрупованими діями впорядкування/видалення та видимою зоною вводу з фокус-рингом. Додає Text,
   Image (через доступне поле завантаження з підписами й alt-поясненням), Row з 2–3 колонок (бачить
   реальну композицію колонок). Форматує текст — активна марка підсвічена. Зберігає чернетку й публікує —
   бачить однозначне підтвердження саме цієї операції.
2. **Автор помиляється й не втрачає роботу.** Вводить невалідний URL посилання — поле лишається відкритим
   із поясненням помилки, посилання не зникає. Видаляє наповнену секцію — фокус переходить на сусідній
   блок (не в `body`). Повільне збереження/завантаження під час паралельної правки не губить текст.
3. **Учень читає урок.** Відкриває reader — прозова колонка з читабельним ритмом (абзаци, h2/h3, видимі
   маркери списків, підкреслені посилання), завдання відокремлене стриманою областю з підписом «Завдання».
   Зображення в межах колонки, не обрізані. Читається в light і dark темі, при 200% зумі без горизонтального
   прокручування, на вузькому екрані.

## Acceptance criteria

(детальна приймальна таблиця — на кроці plan через `acceptance-spec`; тут — межі «готово» на рівні наміру)

- **A-ED1** Кожна секція редактора має видиму межу, підпис типу та згруповані дії; порожня / коротка /
  довга секції однозначно читаються. Зона порожнього rich-text має видиму висоту, padding і фокус-ринг.
- **A-ED2** Image-секція використовує доступне поле завантаження (підписи, ≥44px, клавіатура, alt-пояснення)
  з drop-зоною (перетягування файлу; owner-стер 2026-10-15); довге ім'я файла / alt не розпирають вузький
  екран; preview обмежене шириною секції без crop.
- **A-ED3** Активний стан форматування (`aria-pressed=true`) видимий і не лише кольором; toolbar згруповано
  з переносом; доступні назви зберігаються.
- **A-ED4** Row показує композицію колонок (1/2/3) гридом із переходом у стек за доступною шириною; палітри
  «Додати секцію»/«Додати колонку» видимо підписані; DOM-порядок збережено (без CSS order).
- **A-ED5** loading/error/empty редактора оформлені (Skeleton/ErrorState/EmptyState); для порожнього
  документа палітра додавання лишається видимою; h1 і retry збережено.
- **A-RD1** Reader має прозову типографіку: ритм p/h2/h3, видимі маркери ul/ol, підкреслені посилання,
  обмежену довжину текстового рядка; заголовки уроку не дублюються механічно.
- **A-RD2** Task у reader має стриману власну область і локалізований підпис, відрізняється без опори
  лише на колір; зображення в межах колонки без обрізання.
- **A-RD3** Reader коректний у light І dark темі, при 200% зумі без h-scroll, на вузькому екрані; editor
  коректний у (примусовій) dark-темі адмінки.
- **A-BH1** Save/Publish/upload показують чесний статус саме виконаної операції (success/error); upload-стан
  прив'язаний до конкретного зображення, не спільний; паралельна правка під час повільної операції не
  губить текст.
- **A-BH2** Невалідний URL посилання лишає поле відкритим із поясненням і НЕ видаляє посилання; видалення
  посилання — окрема явна дія.
- **A-BH3** Після add → фокус у новому блоці; після delete → сусідній блок або палітра (не `body`);
  reorder зберігає фокус на тому самому контролі; позиція/межа переміщення оголошується.
- **A-GATE** Повний ordered `make check` зелений (GATE_EXIT=0); зміни shared CSS/стану доведені повним
  e2e, не одним lesson-builder тестом; a11y виміряно в браузері (44px bounding box, фокус, контраст у
  фактичних токенах), не лише axe на зеленому гейті.

## Out of scope

- **Drag-reorder секцій і вільне drag-полотно** — окрема майбутня owner-фаза (рішення 2026-10-13);
  у цій фазі впорядкування лишається ↑/↓, неактивні drag-ручки не малюються.
- **D3 draft-preview + контекст уроку**, **D4 сторінка уроку без відео** (зачіпає оболонку/route +
  playback/transcript, потребує окремого дизайн-проходу й повного e2e), **D5 довгий документ / sticky** —
  після базового оформлення, не тут.
- **Доменна модель документа, санітизація, серверні контракти, round-trip Tiptap**, нові типи секцій
  (code/embed/gallery), здача завдань, мультимова-UI, автозбереження/історія ревізій.
- **Редизайн NorthWind-оболонки, глобальної палітри, шрифтів**; міграція глобального Tailwind-імпорту.
- **Нові рантайм-залежності** (drag-бібліотека тощо).
