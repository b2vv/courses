## 1. Розміщення

Новий модуль `asr` і новий виконуваний файл. Форма скопійована з `media`, бо фаза має ту саму
природу: важка робота з власним часом, власними падіннями й власною вагою на диску.

```
backend/cmd/asr-worker/main.go            композиційний корінь, дзеркало media-worker
backend/internal/asr/
  domain/        draft.go, errors.go      чернетка як стан; мова й сегменти НЕ свої — див. §2
  application/   transcribe.go            Process, Recover, Sweep
  ports/         repository.go, engine.go, media.go, queue.go
  adapters/
    postgres/    repository.go            один рядок на урок (D8-11)
    python/      engine.go                виклик faster-whisper через підпроцес
    asynq/       queue.go, handler.go     черга `asr`
    http/        handler.go               стан чернетки для редактора
backend/migrations/00008_asr.sql          наступний вільний номер (перевірено: до 00007)
```

**Чому окремий виконуваний файл, а не хендлер у `media-worker`.** Не через layering, а через
ресурс: `D8-14a` дає образу Python, CTranslate2 і ваги `large-v3-turbo`, а `mem_limit` росте до
5 ГіБ. Складений у `media-worker` він підняв би ці вимоги для транскодування, яке їх не потребує.

**Чому Python у образі, а не сервіс.** Рушій викликається підпроцесом із того самого контейнера.
Мережевий сервіс додав би відмову, ретрай і контракт там, де їх зараз немає, а `D8-6` уже дає
ідемпотентність на рівні задачі.

## 3. Рішення дизайну

Спека вже несе `D8-1…D8-14a`. Тут — лише те, що вони лишили відкритим на рівні реалізації.

### P-1. Тригер — запит стану, не подія ⟵ `D8-2`

`asr-worker` на старті й за розкладом питає репозиторій: «готові ассети без чернетки цієї
генерації». Крос-модульного запису немає, аутбокса в репозиторії теж, тож подія з `media`
порушила б `D-3`. Падіння між комітом ассета й постановкою задачі нічого не губить: наступний
прохід побачить той самий стан.

Ціна, названа прямо: затримка старту дорівнює періоду опитування. **Період — 60 с**, і це не
вільний параметр: менший не дає нічого, бо сама задача триває хвилини (§6.10), а більший стає
помітним авторові, який щойно завантажив відео й чекає на чернетку.

### P-2. Один рядок, непрозорий документ ⟵ `D8-11`

```
asr_drafts(lesson_id PK, asset_id, generation, state, language, segments jsonb, token, updated_at)
```

`segments` — той самий формат, що віддає редактор, щоб публікація не мала перекладача. Валідація
на вході в модуль (`D8-12`), не на публікації: зациклений вивід моделі має падати тут, а не через
годину на кнопці «зберегти».

### P-3. Таймаут похідний, `NULL` — відмова до запуску ⟵ `D8-9`

`timeout = duration_seconds × K + C`. Числа: **K = 1.0, C = 300 с**, з §6.10 — faster-whisper дає
RTF ~3.2 на 6 CPU, тобто година аудіо ≈ 19 хв; множник 1.0 лишає ~3x запасу на завантажену
машину, а константа покриває старт процесу й завантаження ваг.

`duration_seconds IS NULL` → задача не запускається, чернетка йде в `failed` із названою
причиною. Це не гіпотетика: `AcceptSource` тривалість не перевіряє, ліміт байтовий (2 ГіБ), тож
години аудіо легальні — саме це спростувало «A5 знято» в §11.

### P-4. Рушій викликається підпроцесом, вивід читається зі stdout

Порт `Engine.Transcribe(ctx, path, language) (Result, error)`, де `Result` несе сегменти **і**
`DurationAfterVAD`. Адаптер запускає Python, віддає JSON зі stdout, `stderr` іде в лог без тексту
розпізнаного. Контекст скасування вбиває процес — `exec.CommandContext` із `WaitDelay`, як у
`media/adapters/ffmpeg`.

**`vad_filter=True` — обов'язковий, не опція** (§4.5, замір A01). Без нього модель декодує тишу
й вигадує текст («Thank you.» на кімнатному тоні), а `no_speech_prob` цього не ловить — на
`large-v3-turbo` він вироджений. Саме `duration_after_vad` є ознакою, через яку закривається
`C13`, тож порт мусить його повертати, інакше застосунок не має на чому ухвалити `no_speech`.

**Не** тримаємо модель у пам'яті між задачами: `Concurrency: 1`, і повторне завантаження ваг
коштує ~10 с проти 19 хв роботи (§6.10). Резидентна модель зайняла б 5 ГіБ між задачами.

### P-4a. Межа «немає мовлення» — 1 секунда після VAD ⟵ §4.5

`duration_after_vad < 1 с` → стан `no_speech`, не `ready` з порожнім `segments`. Число грубе
навмисно: заміряне розділення — 0% проти ≥87%, тобто найближчий позитивний випадок лежить за
78 секунд, і тонко підбирати тут нема що. Порог самого VAD — типовий 0.5, не свіпався.

### P-5. Відновлення дзеркалить `media.Recover()` ⟵ `D8-5`

На старті: чернетки в `running` зі старим `updated_at` → назад у чергу або в `failed` із
причиною. Поріг «старий» береться від того самого таймауту P-3, не окремою константою.

### P-6. Мова: `auto` живе тільки в UI ⟵ `D8-8`

Селект пропонує локалі продукту (`en`, `uk`). `auto` — стан селекта, у поле `language` не
потрапляє ніколи. Коли автор лишив `auto`, у рушій іде порожня мова, і модель визначає її сама;
у чернетку пишеться те, що вона повернула, вже як значення.

## 4. Міграція `00008_asr.sql`

```sql
CREATE TABLE asr_drafts (
    lesson_id   uuid PRIMARY KEY REFERENCES course_lessons(id) ON DELETE CASCADE,
    asset_id    uuid NOT NULL REFERENCES video_assets(id) ON DELETE CASCADE,
    generation  integer NOT NULL,
    state       text NOT NULL CHECK (state IN ('queued','running','ready','failed','no_speech')),
    language    text,
    segments    jsonb NOT NULL DEFAULT '[]'::jsonb,
    failure     text,
    token       text NOT NULL,
    updated_at  timestamptz NOT NULL
);
CREATE INDEX asr_drafts_running ON asr_drafts (updated_at) WHERE state = 'running';
```

`ON DELETE CASCADE` на уроці — це `C08` (урок зник під час роботи → чернетка зникає каскадом), на
ассеті — `D8-4`. Частковий індекс обслуговує лише відновлення (P-5), не читання.

**Звірено в дереві, бо перша редакція цього плану помилилась:** таблиця називається
`course_lessons`, не `lessons` (`00003_authoring.sql:35`), обидва ключі — `uuid`. І несиметрія,
яку варто знати: `video_assets.lesson_id` має **`ON DELETE SET NULL`**, тобто ассет переживає
видалення уроку. Чернетка — ні, і це навмисно: без уроку вона нічия. Заодно підтверджено
`declared_bytes BETWEEN 1 AND 2147483648` (`00005_media.sql`), тобто байтову стелю 2 ГіБ, на яку
спирається `D8-9`.

**`no_speech` — окремий стан, а не порожня чернетка** (`C13`): порожній `segments` у стані `ready`
виглядає як зроблена робота.

## 8. Ризики

**Р-1. Рівні доказу — припущення.** Точно та сама позиція, з якої Phase 6 переносила шість
рядків. A02 стоїть другою задачею саме тому.

**Р-2. §6.10 знята на одному відео, одному дикторі, українською.** `D8-8` тримає дві локалі;
англійська не міряна. Якщо на англійській розрив між рушіями інший, рішення `A1` не падає (воно
про CPU і повноту разом), але числа P-3 доведеться перерахувати.

**Р-3. Замір робився на хості розробника, не на воркері.** Абсолютний RTF не переноситься на
іншу машину; переноситься відношення. K у P-3 узятий із запасом 3x саме тому.

**Р-4. Python у образі — нова поверхня.** Ваги, CTranslate2 і залежності Python збільшують образ
і додають щось, що може розійтися з базою при оновленні. `D8-14a` це прийняв свідомо; тут це
записано як ризик, а не як несподіванка.
