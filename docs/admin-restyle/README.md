## Проблема

Публічні сторінки (лендинг/каталог/логін) сильні й на-бренд (лайм+індиго) — поза скоупом. Слабке — **admin**:
виглядає «скомкано/недороблено/кострюбато». Проблема **системна** (спільна оболонка + спільні примітиви
таблиці/картки/форми), не по-екранна.

## Рішення власника (датовані)

- **2026-10-14 — маршрут:** повний прототип усього admin через зовнішній design-AI (Codex + GPT-плагін),
  потім переклад у наш код. (Підтверджено напряму в терміналі Courses 1.)
- **2026-10-14 — гранулярність:** спільні примітиви (один когерентний прохід shell → data-table → form/card;
  екрани успадковують), не 8 окремих редизайнів.
- **2026-10-14 — editor-зріз:** adopt-with-changes прототипу `lesson-studio` — брати візуальну мову, не код
  (`decision-editor-redesign.md`). Це перший зріз фази.
- **Застереження в прод (з editor-рішення, діють на всю фазу):** наші токени, бренд **лайм+індиго** (не чистий
  індиго прототипу), ваги 650/700/750, системний `--btn-primary-*`; БЕЗ паралельного token-шару,
  `--size-zero`/`--color-transparent`, `color-mix`-CTA, `isDisabled` на навігаційних кнопках, власної AdminShell
  прототипу. React Aria + i18n + домен + TanStack Query, не localStorage.

## Консолідований pain-список (власник + жива рев'ю Courses 2 + код-інвентар)

**Системне (на всіх екранах):**
- **Подвійна навігація:** вузький `.admin-rail` (3.5rem) — декоративний `aria-hidden; tabIndex=-1` дубль
  `.admin-sidebar` (main.css:2048). → звести до ОДНОГО нава (прибрати rail безпечно).
- **Плоскі картки:** `.ui-card` (border+shadow) на admin МЕРТВИЙ — admin уживає власні плоскі `.admin-*`
  контейнери → тайли/секції зливаються. → уніфікувати на elevation `.ui-card`.
- **Статуси повз `.ui-pill`:** власні `.admin-course-status/.admin-user-status/.admin-role-tag`
  (main.css:659-773, усі `white-space:nowrap`). → уніфікувати на `.ui-pill` badge.
- **Нав на вузькому їсть контент:** ≤52rem сайдбар стає повноширинним блоком НАД контентом (main.css:2236).
  → collapse у drawer/топ-бар, що не з'їдає висоту.

**Таблиці (спільний data-table):**
- **Row-actions мають бути STICKY** (власник): при горизонтальному скролі дії зникають. → прилипла inline-end
  колонка дій (фон+hairline). Зараз `.admin-user-actions{inline-size:11.5rem}` (main.css:845), fixed, у
  users/participant-reports/refunds.
- **Нема narrow-стратегії:** таблиця лише h-scroll (`white-space:nowrap`), на ~500px переносить title/slug/owner
  посеред слова (UUID по символу). → scroll зі sticky-колонкою АБО stacked-картки.
- **Високі рядки, дії відірвані вправо** (users.index — найохайніший, еталон). → компактні icon-дії/меню.

**По екранах:**
- **analytics** (дашборд): плоскі stat-тайли зливаються, слабка межа груп; «UAH 7,560» дивний letter-spacing.
- **learners** (фільтр-список): статус «Active» впритул до лінку (spacing-баг); рядки без карток/дільників →
  зливаються; прогрес-бар — волосина.
- **participant-reports** (найгірше): репорт = голий «Label: value» дамп без панелі; Resolve/Revoke відкинуті
  далеко вправо; «Open» — текст, не badge. → панель зі структурою, дії прив'язані, статус = pill.
- **refunds** (порожня черга): голий empty-state на величезному полотні. → структурований empty + дизайн
  populated (зараз не видно — нема даних).

**Лишити (не ламати):** eyebrow caps-лейбл + великий H1; правий хедер (Administration · юзер · UA/EN · Sign out);
публічні сторінки.
