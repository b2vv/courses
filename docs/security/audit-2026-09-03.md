# Security audit — Phase 1–2, received 2026-09-03

External static review of the Foundation and public Course catalog slice, scoped to `main`
at the time of the audit. Identity (Phase 3) was outside its scope. No critical or high
findings were reported; the reviewer's verdict was that the system is fit for the local
foundation and public catalog slice it claims.

Every finding below was independently re-verified against the code before any change was
made. All eight held.

## What changed

**MEDIUM-2.** `backend/platform/config` now assembles both DSNs from discrete environment
values using `url.UserPassword`, which percent-encodes credentials. Compose passes
`POSTGRES_HOST`, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `REDIS_HOST` and
`REDIS_PASSWORD` instead of pre-built URLs; `POSTGRES_PORT`, `POSTGRES_SSLMODE`,
`REDIS_PORT` and `REDIS_DB` are optional. Tests assemble a DSN from the password
`p@ss:w/rd?#[]&= x` and assert that `pgxpool.ParseConfig` and `redis.ParseURL` recover it
byte for byte, and that an incomplete or invalid environment is rejected rather than
producing a silently wrong address.

**LOW-1.** Nginx clears `traceparent` and `tracestate` on both proxied locations, so a
public client can no longer force full sampling or write chosen trace ids into telemetry.
Verified live: a request carrying `00-deadbeef…-01` was logged by the API under an
unrelated generated trace id, and the supplied id appeared nowhere in the logs.

**LOW-2.** The Redis password is written to a `umask 077` config file and `redis-server`
is executed with that path, so it never enters argv. Verified live: the password does not
appear in the container's process arguments, and `redis-cli ping` still answers `NOAUTH`
without credentials and `PONG` with them.

**LOW-3.** A `runtime-dependencies` stage runs `npm ci --omit=dev` and the production
image copies `node_modules` from it. Verified live inside the running container:
`playwright`, `@playwright/test`, `msw`, `oxlint` and `@rstest/core` are absent while
`srvx`, `react`, `@tanstack/react-router` and `zod` remain.

**LOW-4.** The repository encodes the slug before handing it to the generated URL builder.
The fix lives in `course-repository.ts` rather than the generated file, so it survives
`make generate` and leaves the drift gate green.

## What is deferred, and why

**MEDIUM-1** belongs to I04, which owns the Nginx auth edge. Two limits are needed there,
not one: a limit on `location /` for SSR-driven catalog and search load, and a much
stricter zone for `POST /api/v1/auth/login`.

The login endpoint is a finding the audit could not see, because Identity did not exist
when it ran. Login currently falls under the general `10r/s, burst=20` API zone, but every
request costs one Argon2id verification at `m=64MiB, t=3, p=2`, and `VerifyDummy` pays the
same price for accounts that do not exist. A single source can therefore drive roughly
640 MiB/s of memory churn from within the allowed rate without holding any valid account.

**LOW-5** and **LOW-6** are TLS-dependent or need a CSP shaped around a UI that is not
built yet. They belong to the pre-deploy hardening checklist together with HSTS, managed
secrets and backups already recorded in the README.

## Already satisfied on the Identity surface

The audit's Phase 3 recommendations are partly met by I03 and were verified live:
`login` and `logout` require exactly one `Origin` header matching the canonical public
origin, which covers CSRF for the only mutations that exist; the session cookie is
`HttpOnly` and `SameSite=Lax`, its `Secure` flag is configuration-driven, and a production
environment refuses to start without HTTPS and secure cookies. Session identity in Query
keys and server-side authorization on admin and learn APIs remain I05–I06 work.
