| Round | Verdict | Finding | Fix |

| R1 on `39d56889` | BLOCK | P2: after a sort change and Back, the uncontrolled field and list kept the typed values while results followed the address | `a07e622a`: controls follow the address |
| R2 on `a07e622a` | BLOCK | P2: the DOM-only update bypassed React Aria TextField state; hovering or focusing the field brought the old text back | `6c74f867`: the field is keyed by the query; the native list is set in place only when it differs, so it keeps focus |
| R3 on `6c74f867` | **PASS** | non-blocking: (1) a `q` change from history while the field is focused re-creates it and focus moves to the page; (2) tests lacked interaction after Forward | (2) added to `catalog.spec.ts`; (1) is accepted below |

Live check on the image from `6c74f867`: sort → Back → hover + click the field → Forward → click the field; the field and the list match the address every time; after the sort change focus stays on the list.

**Author decision, 2026-11-23 (limitation with a mechanism).** When the address's `q` changes while the search field has focus (only through Back/Forward; typing never changes the address), the field is re-created and focus moves to the page body. Check: on `/courses?q=React…`, change the sort, press Back, click the field, press Forward → `document.activeElement` is `BODY`. Keeping focus would need a controlled field, which loses the no-JS form; history navigation moves the reader to a different page state anyway.
