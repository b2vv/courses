## 1. Популярний курс — коректний алгоритм

### 1.1. Чому «найбільше enrollments» хибно
Наївний лічильник enrollments зміщений:
- **вік:** кумулятивний лічильник завжди виграє старим курсам;
- **ціна:** безкоштовні курси набирають більше enrollments, ніж платні;
- **видимість/каталог:** курс, що довше в каталозі або вище в лістингу, збирає більше;
- **малі вибірки рейтингу:** курс з одним 5★-відгуком «обганяє» курс зі 100 відгуками 4.8★.

«Коректно» означає: означити **популяцію** (лише `published`; archived/draft поза), **нормалізувати** сигнали й **розрізнити** два різні питання — *all-time* vs *trending now*.

### 1.2. Два окремі віджети (різні питання)
- **Топ-курси (all-time):** прозорий зважений композит нормалізованих сигналів.
- **Трендові (velocity):** зростання за останній період із time-decay — виринає нові курси незалежно від віку.

### 1.3. Композит для all-time (прозорий, відтворюваний)
```
score(course) = w_e·norm(E) + w_r·norm(R) + w_q·bayes(Q) + w_c·norm(C)
```
- `E` = активні enrollments (`COUNT course_grants WHERE course_id, state='active'`).
- `R` = дохід (`SUM orders.amount_minor WHERE course_id, status='paid'`).
- `Q` = Bayesian-рейтинг (нижче) — гасить малі вибірки.
- `C` = завершення/залученість (avg `position_seconds/duration_seconds` по уроках курсу, або completion-rate).
- `norm(·)` = нормалізація по каталогу (min-max або z-score), щоб різні одиниці були співставні.
- `w_*` — явні, конфігуровані ваги (документуються; це вимога відтворюваності AGENTS.md).

**Bayesian-рейтинг** (IMDb-стиль, проти 1-відгукового 5★):
```
bayes(Q) = (v/(v+m))·avg_stars_course + (m/(v+m))·avg_stars_global
```
де `v` = к-сть відгуків курсу, `m` = поріг довіри (напр. медіана відгуків по каталогу), `avg_stars_global` = середнє по всіх курсах. (Альтернатива — Wilson lower bound для частки позитивних.)

### 1.4. Трендові (velocity з time-decay)
```
trend(course) = Σ_i decay(now − granted_at_i),   decay(Δt) = 0.5^(Δt / halflife)
```
по enrollments (або по доходу через `paid_at`) за вікно (напр. 90 днів), half-life ~14–30 днів. Виринає курси, що ростуть ЗАРАЗ.

### 1.5. Чесний перший крок
Якщо не будувати повний композит одразу: **ранг за recency-зваженими enrollments** (1.4) як первинний + **Bayesian-рейтинг** як якісний гейт/тайбрейкер, і **показувати сирі компоненти** (enrollments, дохід, рейтинг, completion) поруч — щоб число було пояснюване. Повний композит (1.3) — наступний інкремент. Формулу й ваги зафіксувати в коді/доку (AGENTS.md: рішення несе магнітуду/механізм).

## 2. Теги (курсу + відео) — продуктова фіча (пререквізит аналітики по тегах)

### 2.1. Семантика (зі слів власника)
«При створенні [відео] вони **дублюють теги курсу**, але лектор може їх **змінити**.» → **copy-on-create**: при створенні відео його теги = знімок тегів курсу на той момент; далі вони **незалежні** (правка курсу їх не чіпає, лектор редагує per-video). Це НЕ жива референція.

### 2.2. Контрольований словник vs вільний текст
- **Вільний текст** — гнучко лектору, але брудно для агрегації (різні написання одного поняття).
- **Контрольований** — чиста аналітика, але тертя введення.
- **Рекомендація (компроміс):** вільне введення + нормалізація в канонічний тег (lowercase/trim/dedupe/slug), upsert у таблицю `tags` при використанні. Лектор пише вільно, аналітика групує за канонічним тегом.

### 2.3. Схема (ескіз)
```
tags(id, slug unique, label)
course_tags(course_id, tag_id)            -- набір тегів курсу
video_tags(video_id|lesson_id, tag_id)    -- копія при створенні, далі незалежна
```
Join-таблиці (а не `text[]`): дешевий rename тега, чисті `GROUP BY tag_id`, FK-цілісність. Відкрите продуктове питання: теги чіпляються до `video_assets` чи до `course_lessons`? (відео належить уроку — визначити на spec майбутньої фази).

### 2.4. Обсяг (чому окрема фаза)
Schema + домен + authoring-UI (поле тегів у редакторі курсу й у редакторі відео/уроку) + inherit-on-create + правка лектором + міграція наявних курсів (порожні теги). Це фіча редактора курсів, не аналітика. Найбільша з трьох частин.

## 3. Аналіз по тегах (ПІСЛЯ §2)
Коли теги є: курсів на тег, enrollments на тег, дохід на тег, середній рейтинг на тег, хвилини/к-сть відео на тег, watch-time на тег. На рівні відео теги дають контент-аналіз (які теми реально дивляться). **Блокується §2.**

## 4. Аналіз по довжині відео (джерело Є вже — 🟢)
`video_assets.duration_seconds` наявний, тож будується без нової продуктової схеми.
- **Дешево зараз:** сумарні хвилини каталогу; середня/медіанна довжина уроку; гістограма розподілу (бакети <5хв / 5–15 / 15–30 / 30+); довжина на курс/модуль.
- **Потребує `lesson_progress` (теж є):** watch-through ratio = avg `position_seconds / duration_seconds` на відео → проксі drop-off («довгі відео кидають?»). Це дешевший проксі за повноцінний event-stream retention (який §9 analytics-plan відніс у 🔴).
- ⚠️ `duration_seconds` nullable → до публікації відео NULL; агрегати рахувати `WHERE duration_seconds IS NOT NULL` і чесно підписувати покриття.

## 5. Фазування (залежності, порядок)

| Частина | Нова прод-схема? | Залежить від | Орієнтовний розмір |
|---|---|---|---|
| Популярний курс (§1) | ні (лише SQL+UI) | — | середній |
| Довжина відео (§4) | ні (`duration_seconds` є) | — | малий |
| Теги-фіча (§2) | **так** (tags + join + UI) | — | великий |
| Аналіз по тегах (§3) | ні (аналітика) | §2 | середній |

**Рекомендований порядок (після поточної admin-stats):**
1. **Популярний курс + довжина відео** — чиста аналітика, 0 нової продуктової схеми, обидва джерела є. Можна однією аналітичною фазою.
2. **Теги-фіча** — продуктова робота в редакторі курсів/відео.
3. **Аналіз по тегах** — коли теги наповняться даними.

**Межа з поточною фазою:** нічого звідси в admin-stats не входить. (Виняток-кандидат: базова «довжина відео» §4 дешева й джерело є — якщо власник захоче, її МОЖНА підмішати в домен «Операції» поточної фази; зараз лишаю відкладеною за прямою вказівкою.)

## 6. Відкриті продуктові питання (для spec майбутньої фази)
- Ваги `w_*` і поріг `m` композиту §1.3 — хто калібрує, за якими даними.
- Теги чіпляються до `video_assets` чи `course_lessons` (§2.3).
- Контрольований словник vs вільний-з-нормалізацією (§2.2) — фінальний вибір.
- Міграція наявних курсів/відео при вводі тегів (порожні? backfill з назви?).
